## Introduction
Managing hardware devices (GPUs, CPUs, NICs) in data centers often requires multiple tools, each with its own device identification method. This inconsistency complicates device correlation and management, especially across different vendors. The **Common Unique Identifier (CUID)** solves this by providing a deterministic, unique identifier for each device type, enabling consistent referencing and easier integration.

### What is CUID?

The **Component Universal Identifier (CUID or CUUID)** is generated by combining device-specific data according to standards:

- **Header** (128 bits): bits 383–256
- **Reserved** (128 bits, zero): bits 255–128
- **Device fingerprint** (128 bits): bits 127–0 (e.g., PNPID, serial number, UUID, MAC address)

A **secondary CUID** is derived by hashing the primary CUID, optionally with a salt (a random 112-bit secret). This obscures hardware details from lower-privilege software and prevents precomputed table attacks. The hash uses SHA-224 on the primary ID plus salt. If no salt is provided, a default (all zeros) is used. The salt must be kept confidential and consistent across the organization.

### CUID File

Privileged applications generate and share secondary CUIDs with non-privileged users via a file (the **CUID file**) or IPC. The file should be stored in `/tmp` or a `tmpfs` directory and readable by non-privileged users. It is updated by a daemon, boot script, or cron job.

#### Example CUID File Format

```ini
[GPU:0]
secondary_cuid=a430166f-0027-8ef5-8d5d-01981daf3276
device_node=/sys/class/drm/renderD128
last_update=1753987166

[CPU:0]
secondary_cuid=6866ba59-7bc5-47bb-98a1-789914976841
package_core_id=0:0
last_update=1753987166

[NIC:0]
secondary_cuid=4ef20f08-5a90-8000-8000-33158680c000
device_node=/sys/class/net/enp131s0
last_update=1753987166

[PLATFORM]
secondary_cuid=f2b69d02-4e41-418d-bc15-e0994eebdfd9
last_update=1753987166
```

- **GPU:** `device_node` links the CUID to hardware.
- **CPU:** `package_core_id` identifies cores (`package_id:core_id`).
- **NIC:** `device_node` links to the network device.
- **PLATFORM:** Only the secondary CUID is listed.

`last_update` is a Unix timestamp for the last modification.

#### Including Primary CUID (Privileged Users)

Privileged users can map `primary_cuid` to `secondary_cuid`:

```ini
[GPU:0]
primary_cuid=8faa1b22-c964-4d08-9eab-f0c19743dc5b
secondary_cuid=a430166f-0027-8ef5-8d5d-01981daf3276
device_node=/sys/class/drm/renderD128
last_update=1753987166
```

> **Note:** The file contains sensitive information. Restrict access to `primary_cuid`.

### CUID Tool Overview

The CUID tool supports both privileged and non-privileged users:

#### CUID Library

- Discovers hardware and constructs primary CUIDs.
- Generates secondary CUIDs via hashing.
- Provides APIs for device info and identifiers.

#### Command Line Interface (CLI)

- Uses the library to detect devices and generate CUIDs.
- Allows creation of primary/secondary CUIDs.
- Simplifies device management and integration.

#### Example: Detecting PCI Device Events with libudev

You can use `libudev` to monitor PCI device plug and unplug events. Below is a sample C program that listens for PCI device events and prints relevant information:

```c
#include <libudev.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/select.h>
#include <unistd.h>

int main() {
    struct udev *udev;
    struct udev_monitor *mon;
    struct udev_device *dev;

    // Create udev object
    udev = udev_new();
    if (!udev) {
        fprintf(stderr, "Failed to create udev object\n");
        return 1;
    }

    // Create a udev monitor to listen for PCI device events
    mon = udev_monitor_new_from_netlink(udev, "udev");
    udev_monitor_filter_add_match_subsystem_devtype(mon, "pci", NULL);
    udev_monitor_enable_receiving(mon);

    // Get the file descriptor for the monitor
    int fd = udev_monitor_get_fd(mon);

    printf("Listening for PCI device events...\n");

    while (1) {
        // Set up the timeout
        struct timeval timeout;
        timeout.tv_sec = 5;  // 5 seconds timeout
        timeout.tv_usec = 0;

        // Check if there are any events
        fd_set fds;
        FD_ZERO(&fds);
        FD_SET(fd, &fds);

        // Wait for an event or timeout
        int ret = select(fd + 1, &fds, NULL, NULL, &timeout);
        if (ret > 0 && FD_ISSET(fd, &fds)) {
            // Receive the device event
            dev = udev_monitor_receive_device(mon);
            if (dev) {
                printf("Device action: %s\n", udev_device_get_action(dev));
                printf("Device node: %s\n", udev_device_get_devnode(dev));
                printf("Subsystem: %s\n", udev_device_get_subsystem(dev));
                udev_device_unref(dev);
            }
        } else if (ret == 0) {
            // Timeout occurred, perform other logic
            printf("Timeout occurred, performing periodic tasks...\n");
            // Add your periodic logic here
        } else {
            // Error occurred
            perror("select");
        }
    }

    // Cleanup
    udev_monitor_unref(mon);
    udev_unref(udev);

    return 0;
}
```

This code sets up a monitor for PCI device events and prints details when devices are added or removed. You can extend the periodic logic section as needed for your application.
