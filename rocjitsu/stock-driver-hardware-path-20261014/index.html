    Date: 2026-10-14. Checkout: users/agutierr/p4v-kfd-map-trace at 07988db4b20d25ddf8cab50a008791255ec96532, with the working-tree changes described in docs/qemu-vfio.md. No commit was created.

    Guest driver and image¶

    The source package was tmp/amdgpu-dkms_7.1.3.31500000-2390945.24.04_all.deb (SHA-256 edf6b629f2cb2d6091aac531c0787aee2387bdc0748a91f21ea38c6c10970ffb). The freshly extracted DKMS source received local driver bug-fix patches 0001 through 0008 in numeric order. Those patches are no longer included in this repository. patch-application.log records their checks and application; build.log records the module build against /usr/src/linux-headers-6.17.0-23-generic. Patch 0011 is an optional diagnostic and was not applied to this production module. Other historical experimental patches were also absent. The scratch DKMS source acquired temporary printk diagnostics after the production module was staged; it is not the source of the module inside this image.

    The removed fixes addressed independent VM-update and KFD retry error paths in this pinned driver: link a page table only after its clear succeeds, correct SDMA dependency fence ownership, abort unsubmitted failed PT/PDE jobs, publish CPU TLB sequence after HDP flush, retry a failed compute TLB flush, and retain KFD unmap and TLB-flush work for retry. The later zero-patch UC workload did not exercise those failures. For this tested driver version, these controls also did not establish SVM invalidation acknowledgement or error ownership across failures for cacheable peer mappings. That contract remained open for the later cacheable-coherence work.

    Cacheability boundary checked after this control¶

    The selected guest configuration has revision_id=1. In the pinned DKMS source, amd/amdgpu/gmc_v12_1.c selects MTYPE_UC for remote VRAM on GC 12.1.0 A0 (gmc_v12_1_get_coherence_flags, around lines 545-580). The KFD mapping passes through gmc_v12_1_get_vm_pte; no simulator-specific driver change is needed to obtain this policy. The GFX12 PTE decoder reads bits 54-55 and maps the UC encoding to Mtype::UC.

    Translated vector reads whose full cache line maps to local VRAM now use the existing Simdojo V$ and L2 components. Each clean tag keeps the exact address-space handle, physical line, raw PTE memory type, permissions, and local backing epoch. A hit checks its live transport session and VM namespace; local VRAM writes, HDP flushes, and fabric maintenance retire stale clean tags. Translated scalar reads and vector stores still use direct VM access. The existing same-host peer guest checks ordinary transport and backing effects; it does not demonstrate an owner cache hit or a cacheable peer alias. The VFIO peer adapter rejects a nonzero-VMID PTE with a memory type other than UC before submitting its fabric effect. The VM translation also retains the raw GFX12 PTE memory-type encoding so an NC-to-RW change cannot pass a deferred rewalk merely because both encodings currently share the broad Mtype::RW cache class. VMID-0 GART requests retain their uncached MES/SDMA route.

    The focused VfioTargetGrants.Gfx12GartPeerReadWriteUsesFabricWithStockPageTableWalks test used the real GFX12 PTE decoder and a live two-function VFIO grant. It passed after checking that process-VMID RW peer reads and writes produce no effect, a UC peer read produces one effect and the expected bytes, and exact UNMAP denies a later read. The test was run from tmp/p3v-alias-observation-release/tests/rocjitsu_tests after rebuilding rocjitsu_tests and rocjitsu_bin; the local socket test required the unsandboxed test runner. All 33 VfioTargetGrants and VfioDeviceHost CTest cases passed in 2.16 seconds. The GpuVmTranslation.Gfx12PeerRewalkDistinguishesNcFromRwPteEncoding test also passed, proving that a PTE type change with the same broad cache class and physical address is rejected on rewalk.

The VFIO grant and canonical backing must remain live through cache fill, fabric maintenance, effect, completion, and retirement. The current A0 configuration has no such peer PTE. The available same-host topology cannot qualify the separate-host exit gate.

    Translated local cache and same-host rerun¶

    The local vector-read path uses the existing V$ and L2 cache components with an exact address-space namespace. It remains restricted to complete local cache-line translations and a PCI backing that advertises local write and HDP publication. The functional visibility epoch retires clean local tags after trapped VRAM writes, SDMA local writes, HDP flushes, and fabric maintenance. An SDMA write can publish while it holds cache maintenance; publication does not recursively acquire the domain lock. Scalar reads, vector stores, and cacheable peer PTEs remain outside this path.

    The rebuilt rocjitsu_tests and rocjitsu_bin targets passed the focused TranslatedLocalCache.ExactHandlePtePolicyAndFabricBoundaryRefetchOwnerData, GpuDevice.AcceptsTheHdpFlushTheDriverIssues, GpuDeviceSdma.RegisterBackedQueueRoutesAddressesOutsideTheGartApertureToVram, and both GpuDeviceHdpFlush tests. The selected PCI, VM, MES, KFD, SDMA, and cache regression run passed 206 of 237 cases inside the sandbox; the other 31 were VFIO cases whose Unix socket creation was denied with Operation not permitted. All 33 VfioDeviceHost and VfioTargetGrants cases passed when rerun with local Unix socket access. clang-format --dry-run --Werror on the changed cache implementation and PCI test, and git diff --check, passed.
