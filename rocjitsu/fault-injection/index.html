    Fault injection¶

    The fault-injection library creates deliberately modified AMDGPU code objects for experiments with synchronization, LDS and atomic address failures. It runs offline on the host: callers supply an image, select a qualified operation, and receive a mutant image or a typed error. It neither initializes HSA nor dispatches GPU work.

    The internal C++ library and rj_code_mutate CLI perform the same mutation. ConSan is an optional consumer of the output; both the library and CLI build and run host tests with the ConSan compiler, runtime, and analyzer disabled. There is no persistent selection, manifest, or replay-bundle format.

    Architecture and lifetime¶

    This flow shows the complete-barrier Drop path and its shared DBI transaction boundary. The LDS recipe uses the same source facts and a fresh Instrumentor fork, with its own instruction qualification and address replacement:

    flowchart TD
    Source[Immutable source context] --> Facts[Concrete decode and all-entry direct CFG ownership]
    Source --> Seed[Instrumentor seed: cached full-text facts]
    Facts --> Inventory[Exact-kernel inventory of complete barriers]
    Seed --> Inventory
    Inventory --> Selection[Exact handle or logical ordinal]
    Selection --> Recipe[Drop recipe: ordered replacement requests]
    Seed --> Batch[Fresh Instrumentor fork sharing source facts]
    Recipe --> Batch
    Batch --> Transaction[Shared validation, trampoline layout and CodeObjectPatcher]
    Transaction --> Mutant[Owned mutant ELF in result.image]

    FaultMutationContext owns one immutable copy of the input. Retain it in the input/session owner until all discovery, selection, and apply operations finish. One context can serve many requests for that original image; each apply produces an independent mutant. A session handling several inputs keeps a separate context for each. To analyze or mutate an emitted image, create a new context from its bytes.

    The context supplies target, section, and owner facts independently of any barrier. It caches the fixed all-entry ownership analysis; Drop separately caches per-kernel barrier qualification. Full-text structural facts belong to a retained Instrumentor seed: references in unreachable code still matter to byte editing. Each apply forks a fresh request batch that shares those immutable facts and repeats request-specific validation. The batches have independent queues and patch attempts; they do not inherit previous mutations. Facts are reusable for the same immutable source and analysis profile. LDS discovery can additionally borrow complete hardware-root and execution-owner facts from KernelOwnership; Drop retains its exclusive direct-CFG qualification. Selections expire with their source context and cannot be replayed in another context, even if its input bytes are identical. Drop selections expose kind, owner, and barrier snapshots; LDS selections expose kind, selected owner, and site snapshots, including every affected execution owner. Those snapshots remain readable after expiry but cannot authorize a mutation. The in-process API does not require callers to supply a target or content digest.

    The common source context and admission live in fault_mutation_context.{h,cpp}. The Drop and LDS recipes live in drop_barrier.{h,cpp} and lds_wrong_address.{h,cpp}, respectively. Each recipe includes the common context header; LDS callers include lds_wrong_address.h.

    The library reuses the ISA registry and concrete decoder, BasicBlock and KernelScopeSpec, descriptor scanning, instruction builders, and CodeObjectPatcher. Concrete identity is preserved, including the differing gfx1250/gfx1251 decoder features. The host-only tests link the existing static-analysis composition and model ISA providers; simulator execution support is not an admission condition. See ISA target providers and the test target wiring.

    Generic mechanics and recipe semantics have separate responsibilities:

    • InstrumentationKind::ReplaceWithInst accepts owned expected and replacement bytes at each original-text anchor. Its shared backend checks source structure, complete instruction extents, expected bytes, references, clauses, and replacement encoding before changing a private image through CodeObjectPatcher. It does not decide which barrier should be removed or prove recipe ownership. Generic transaction tests belong to the DBI replacement suite.
    • qualify_static_barriers and the Drop frontend establish admitted logical members and choose the corresponding NOP bodies. Qualification uses the same full-text instruction boundaries and clause facts as the checked-edit transaction, including facts from unreachable text. Recipe tests verify output semantics; emission does not run a second FI domain validator.
    • The LDS frontend checks a supported instruction and register allocation, then uses a target-specific ISA helper, such as the RDNA4 source-preserving helper to change only its encoded address field. It sends the complete replacement through the same transaction; the helper does not choose a fault or a register.
    • Instrumentor owns both replacement transactions and observational instrumentation. Each selected barrier member becomes a branch to an appended cave containing s_nop 0 and a branch back to the next original instruction. The original barrier is never replayed. Drop supplies no probes and requires no additional registers or spill storage. The shared writer grows .text and updates ELF layout and descriptor entry displacements as needed; original file offsets and whole-image byte identity are therefore not preserved. Unselected guest instructions retain their text-relative offsets and encodings, and descriptor wave and resource fields retain their values. Generic replacement can compose with observations, but this recipe queues only replacement requests. See the DBI design for the shared contract and site-range meanings.

    Features and status¶

    Feature Status and main boundary References
    Complete barrier Drop Implemented for the target/wave forms below. Removes one logical barrier: an ordered two-member signal/wait pair or one true full-barrier instruction. A half-pair is never a singleton. StaticBarrier / family policy, qualification, analysis regressions, Drop regressions
    LDS wrong address Implements the exact scalar, two-address, subword, D16 and transpose matrices below on seven concrete targets and ten target/wave profiles. Replaces only the address VGPR with an explicitly supplied, distinct, allocated VGPR. Direct and shared execution owners must all satisfy allocation and bank requirements. LDS API, library tests, CLI tests
    Atomic wrong address (AtomicWrongAddress) Lists all owned atomic sites before recipe admission. Mutates the signed24 byte offset of twelve-byte FLAT/GLOBAL atomics on gfx1200/gfx1201 wave32/wave64 and gfx1250/gfx1251 wave32, preserving the operation's alignment. Unsupported forms retain their ordinals and fail on apply. Atomic API, library tests, CLI tests
    Exact and logical-ordinal selection An exact kernel name chooses one inventory; an exact context-bound handle takes precedence over the zero-based logical ordinal. Invalid exact requests fail without fallback. Ordinal zero chooses the first barrier by first-member offset, or the first LDS instruction or atomic site by source offset. Atomic ordinals include unsupported forms. There is no race ranking or legacy physical-index adapter. DropBarrierSelector, select_drop_barrier, LdsSelector and select_lds_wrong_address, selection regressions
    Multiple kernels in one text section Discovery checks all entries before exposing one exact kernel's inventory. FaultMutationContext, ownership analysis, sibling preservation tests
    Shared DBI instruction replacement Consumed through InstrumentationKind::ReplaceWithInst. One transaction replaces complete source instructions through trampolines. Drop supplies one 4-byte NOP body for each qualified 4-byte barrier member. This does not widen observational trampoline-anchor admission. Instrumentor contract, DBI design, transaction tests, replacement tests
    Offline CLI Lists current-input sites and emits one complete Drop, supported LDS address mutation, or supported atomic address mutation using the same library. usage, frontend, integration tests
    Persistent selection files and replay bundles Not provided; no durable replay format is committed. —
    Helper, indirect-flow and firmware-preload ownership LDS can list sites reached through shared helpers, recovered calls and supported CDNA preload entry points when complete ownership is proved. Recovered calls may still prevent emission. Drop requires independent direct control flow; unresolved flow remains rejected. ownership tests
    Other mutation recipes and composition Planned. Barrier movement, ordinary address changes, order/scope changes, grouped or destructive partial Drop, and multi-mutation composition are not implemented here. —
    Multiple text sections or dynamic occurrence selection Unsupported. —

    A caller uses discover_drop_barriers with an exact kernel name to obtain an inventory, select_drop_barrier to choose a complete logical barrier, and apply_drop_barrier to emit it. Each operation returns FailureOr and a typed FaultMutationError; the API header defines the arguments, lifetime contract, and result fields. DropBarrierResult::image owns the emitted ELF; selection.barrier().members retains the ordered original members and selection.owner() retains pristine owner offsets. Rescan the emitted image for its section and descriptor file locations. Fresh CFG block boundaries can differ because of the added branches. FI does not expose a second generic edit plan, validator, or writer.

    Atomic callers use discover_atomic_wrong_address, select_atomic_wrong_address and apply_atomic_wrong_address with the same context lifetime rule. Inventory ordinals include unsupported atomic forms. A delta must be positive, at most 0x7fffff bytes, and a multiple of four bytes and of the selected operation's natural alignment: eight bytes for 64-bit atomics, four for 32-bit and packed 16-bit-pair atomics. Compare-and-swap uses the memory element's width, not the combined compare/replacement payload width. The resulting offset must fit the signed24 field. These checks preserve an already aligned runtime address; the caller remains responsible for the original address's alignment and both addresses' validity. CDNA5 scale_offset does not change the immediate's byte units. Mutation changes only the immediate and preserves operands, return/CAS behavior, modifiers, waits and the guest continuation. Successful discovery does not guarantee that the shared writer can emit an input's layout.

    Target coverage and qualification¶

    fault_mutation_capabilities() lists transformation admission from the linked default ISA registry and family policy used by discovery and apply. The current bindings cover seven concrete targets and ten target/wave combinations:

    Family Concrete target Wave size Complete logical barrier
    RDNA3 gfx1100 32 Full s_barrier singleton, workgroup
    RDNA3 gfx1100 64 Full s_barrier singleton, workgroup
    RDNA4 gfx1200 32 Builtin signal/wait pair, workgroup ID -1
    RDNA4 gfx1200 64 Builtin signal/wait pair, workgroup ID -1
    RDNA4 gfx1201 32 Builtin signal/wait pair, workgroup ID -1
    RDNA4 gfx1201 64 Builtin signal/wait pair, workgroup ID -1
    CDNA5 gfx1250 32 Builtin signal/wait pair, ID -1 workgroup or -3 cluster
    CDNA5 gfx1251 32 Builtin signal/wait pair, ID -1 workgroup or -3 cluster
    CDNA3 gfx942 64 Full s_barrier singleton, workgroup
    CDNA4 gfx950 64 Full s_barrier singleton, workgroup

    The table above describes Drop only. lds_wrong_address_capabilities() separately reports the exact seven-target, ten-target/wave LDS matrices below. LDS admits independent direct CFGs and shared sites with complete affected-owner facts. Every affected owner must satisfy allocation and, on CDNA5, agree on the proven address bank. GDS encodings are excluded using the concrete target's field; the CDNA ACC data selector is preserved. The ownership and emission limits are described below. A target is omitted if its decoder or binding is not linked. Other targets, waves, and DS forms are not advertised by this recipe; the Drop table does not imply LDS support.

    The host regression matrix covers discovery, exact/ordinal selection, emission, concrete decoding, and preservation for these rows. RDNA3 has its own instruction encodings and descriptor-selected wave modes; the shared singleton representation does not imply CDNA encodings or wave64-only admission. CDNA1/CDNA2 and unregistered targets are not admitted. A different provider composition may expose fewer bindings.

    Trap-handler IDs -2 (RDNA4/CDNA5) and -4 (CDNA5) are rejected, including when they appear before an otherwise admitted user barrier. Their operations are inert outside privileged mode and must not consume a user barrier's logical ordinal. See the RDNA4 ISA, section 5.6 and Table 24 and CDNA5 ISA, section 5.6 and Table 21. CDNA5 ID -3 is admitted as a static cluster barrier, but its operations are inert for nonclustered dispatches and single-workgroup clusters. A Drop experiment also assumes a valid pristine protocol: exactly one cluster signal per workgroup, issued by one wave after workgroup synchronization, with every wave waiting for the cluster barrier. Cluster membership alone does not establish that protocol. See CDNA5 ISA, section 5.6.6, page 51. Selecting -3 records these preconditions in DropBarrierResult; offline qualification verifies neither workgroup size nor this protocol.

    Compiler output must still fit the admitted instruction shape. In LLVM's barrier lowering, optimization with a known single-wave workgroup can produce the admitted same-block cluster signal/wait pair. Otherwise, including for multi-wave workgroups, lowering uses workgroup s_barrier_signal_isfirst and a conditional cluster signal in a different block from the cluster wait. Both signal_isfirst and cross-block pairs are outside this profile. This compiler-shape limitation comes from source inspection; it does not qualify physical GPU execution.

    These are host transformation capabilities. Neither the listing nor a successful mutation establishes GPU execution or detector qualification. DropBarrierResult leaves those evidence states Unverified; LdsResult does not itself contain execution or detector evidence fields. A removed barrier may be redundant, unreachable in a particular run, or insufficient to cause a race; successful execution alone also does not establish a detector finding.

    Current limits¶

    Inputs must be little-endian AMDHSA ET_DYN ELF64 images with one executable .text. ABI admission follows the shared ELF reader and DBI patcher. Text and descriptors require unambiguous file-backed load mappings. Additional PT_LOAD mappings that overlap any of their file bytes are rejected, including partial aliases at different virtual addresses: changing one file word would otherwise change bytes at an unanalyzed loaded address too. File ranges that only touch these boundaries and zero-file-size segments at disjoint addresses do not create file aliases. This is FI's loaded-ownership admission, not a new requirement for generic Instrumentor replacement.

    Every admitted 64-byte kernel descriptor must also remain immutable under the supported ROCr dynamic relocations. FI rejects their 4-byte or 8-byte writes when any byte overlaps a descriptor, including a write beginning in preceding loaded padding or a write into an unselected sibling's descriptor. Protecting the complete descriptor keeps entry, wave, preload, and other descriptor facts bound to the same file snapshot. Explicit-target static relocation metadata and dynamic writes outside descriptors retain the existing shared admission. This check does not resolve relocation values or add ABI qualification.

    The Drop ownership profile admits closed direct CFGs with independent kernel entries. It rejects shared helpers/calls, indirect or unresolved flow, firmware-preload entries, and declared executable owners outside the analyzed text. LDS uses complete ownership facts for supported shared-helper, recovered-call and CDNA preload profiles as described below. Non-aliasing unselected sections are preserved; their executable flag alone does not imply another text section. Additional allocated executable sections must decode completely and satisfy the shared source checks before discovery can return an inventory. Detailed admission and diagnostics are in the source context and shared Instrumentor contract.

    The LDS address profiles cover these exact instruction families:

    Concrete target Waves Scalar forms Two-address forms
    gfx1100, gfx1200, gfx1201 32, 64 ds_load_b32/b64/b96/b128, ds_store_b32/b64/b96/b128 ds_load_2addr_b32/b64, ds_store_2addr_b32/b64, ds_load_2addr_stride64_b32/b64, ds_store_2addr_stride64_b32/b64
    gfx942, gfx950 64 ds_read_b32/b64/b96/b128, ds_write_b32/b64/b96/b128 ds_read2_b32/b64, ds_write2_b32/b64, ds_read2st64_b32/b64, ds_write2st64_b32/b64
    gfx1250 32 ds_load_b32/b64/b96/b128, ds_store_b32/b64/b96/b128 Excluded by the retained gfx1250 profile.
    gfx1251 32 ds_load_b32/b64/b96/b128, ds_store_b32/b64/b96/b128 ds_load_2addr_b32/b64, ds_store_2addr_b32/b64, ds_load_2addr_stride64_b32/b64, ds_store_2addr_stride64_b32/b64

    Additional subword and transpose forms are admitted only on their listed targets:

    Concrete target Subword forms Transpose forms
    gfx1100, gfx1200, gfx1201 ds_load_i8/u8/i16/u16, ds_load_u8_d16, ds_load_i8_d16, ds_load_u16_d16 and their _hi variants; ds_store_b8/b16 and their _d16_hi variants None
    gfx942 ds_read_i8/u8/i16/u16, ds_read_u8_d16, ds_read_i8_d16, ds_read_u16_d16 and their _hi variants; ds_write_b8/b16 and their _d16_hi variants None
    gfx950 Same subword families as gfx942 ds_read_b64_tr_b16
    gfx1250 Same subword families as gfx1100/gfx1200/gfx1201 ds_load_tr8_b64, ds_load_tr16_b128
    gfx1251 Same subword families as gfx1100/gfx1200/gfx1201 ds_load_tr4_b64, ds_load_tr6_b96, ds_load_tr8_b64, ds_load_tr16_b128

    All admitted gfx1100/gfx1200/gfx1201 forms support both descriptor-selected waves: Wave32 uses descriptor granules of eight VGPRs and Wave64 uses four. gfx1250/gfx1251 always use Wave32 with descriptor granules of sixteen VGPRs, including code objects that omit the legacy Wave32 enable bit.

    The gfx1251 two-address profile preserves one complete eight-byte VDS instruction, including both offsets. The gfx1250 two-address exclusion is retained from its original ConSan split-replay qualification; it is a profile policy, not a limitation of the raw address-field setter. Its existing transpose profiles remain admitted. ADDTID operations use M0 and lane ID without an address VGPR and are excluded. RDNA3 has no corresponding transpose opcodes; concrete decoding rejects them.

    A slash-separated width suffix denotes each named form, for example ds_load_b32/b64 denotes ds_load_b32 and ds_load_b64; similarly, ds_load_i8/u8 denotes ds_load_i8 and ds_load_u8. The two matrices cover 209 concrete target/form profiles, expanded to 299 target/wave/form capabilities. Only the address VGPR selector changes; the two offsets, stride semantics, data and destination tuples, and CDNA ACC bit are preserved. GDS instructions remain excluded using RDNA3 bit17 and CDNA3/4 bit16. gfx1250/gfx1251 require a statically proven address bank and check the replacement selector against that bank's allocated register window.

    The LDS inventory contains complete, reachable instructions of the admitted forms in the kernel; clause members are not advertised. It does not require a barrier or successful Drop qualification. The replacement register must be explicit, representable in the eight-bit encoded address field, different from the original, and inside every affected descriptor's allocated ordinary VGPR window. CDNA5 sites are omitted if any affected owner enables COMPUTE_PGM_RSRC3.ENABLE_DYNAMIC_VGPR. The descriptor count cannot prove the live allocation after s_alloc_vgpr; no dynamic allocation proof is implemented. Unrelated owners do not exclude an otherwise qualified site. A shared instruction is one physical site even when selected through either owner. Discovery retains all owners before applying the exact kernel filter, and requires all gfx1250/gfx1251 owners to prove the same address bank at that instruction. Bank analysis uses each concrete target's MODE capability: gfx1250 enables its setreg fixup and adjacency hazard; gfx1251 uses ordinary right-justified HWREG slices without that fixup. Preload roots use the shared hardware-entry policy. A shared exact handle may be rebound through another affected owner of the same immutable source; unrelated owners and foreign or expired contexts cannot authorize it.

    These owner facts do not change emission: LDS uses the existing ReplaceWithInst trampoline pipeline. Recovered-call inventory can succeed while apply rejects retained PC-relative references when growth moves storage. Out-of-range trampolines also remain unsupported; neither failure publishes a mutant. No stationary replacement option or PC-builder relocation is introduced. For CDNA3/4 this window ends at the accumulator allocation base when that base is below the total allocation. These checks do not prove that the register has been initialized or holds a valid LDS address at runtime: the caller must arrange both. Static mutation affects every execution of the selected instruction. Target/wave/form combinations outside the listed matrices and ownership cases without complete proof remain unsupported.

    Barrier qualification is all-or-nothing for a kernel's analyzed reachable scope: an unsupported form or incomplete barrier rejects that kernel's entire inventory, even when other complete barriers are present. This is the current Drop admission policy. Per-kernel wave or barrier qualification failures leave independent sibling kernels available. Failures in the shared structural or ownership checks reject the whole image profile, including unknown flow in an unselected owner.

    A split pair must complete in the same basic block, although ordinary instructions may separate its members. Partial, interleaved, cross-block, named/dynamic/lifecycle and signal_isfirst forms, as well as barriers inside clauses, are rejected. A direct loop can contain a qualified static barrier; removal affects every executed occurrence of that position. There is no selection of the Nth dynamic occurrence or proof of convergence.

    Each member's outgoing and return branches must fit the shared trampoline pipeline's signed 16-bit dword displacement. Discovery can succeed while apply fails because an appended cave is out of reach, including for a large text section. No partial mutant is returned and the source context remains unchanged. Drop introduces extra branches and NOPs, so it does not preserve instruction counts or timing. Host transformation tests do not establish physical execution.

    Apply also rejects retained s_getpc_b64 / s_get_pc_i64 when text growth moves allocated storage or consumes a loaded file or zero-fill tail. This shared replacement guard checks the whole image, including sibling kernels: unchanged instruction bytes alone cannot preserve linked PC-relative data addresses. The restriction is conservative and can reject a safe target when unrelated allocated metadata moves. Complete address-builder relocation is not implemented; see replacement validation.

    Retained direct branches also reject when growth moves their source and destination differently, including later allocated sections and loaded tails. Full-text source facts include unreachable references, so discovery may succeed while apply rejects the complete Drop batch.

    For ConSan use, follow the fresh-prepare integration contract. Fresh prepare currently requires a single-kernel image. Sibling-preserving multi-kernel mutants cannot use this path; any remaining barriers must satisfy ConSan's qualified gfx1250 wave32 workgroup-barrier profile. The mutant must also satisfy ConSan's other input restrictions; fresh preparation does not establish detector qualification. Mutation admission and detector admission are separate decisions.

    Optional compiled corpus regression¶

    RJ_FAULT_INJECTION_CORPUS_OBJECT is empty by default. Without it, the FaultDropBarrier.CompiledCorpusCompleteDrop test is not registered; the synthetic host regressions remain available. Supplying an existing device ELF enables the corpus test, but CMake does not verify its provenance or digest. The test expects the compiled fa_barrier_epoch kernel and checks complete Drop, emitted instructions, and preservation. It does not run the GPU kernel.

    To reproduce the historical reference fixture, use fa_barrier_epoch.hip and utils.hpp from rocjitsu-test-corpus revision c5e3c38464d7440ef7dc977ed95419d7544afe50. The recorded build used TheRock SDK 10.1.0a20260812, AMD clang 23.0.0git (LLVM revision a01cdbd92d1f931738a4897502747a68ae36eccf). Prepare this version in a per-worktree SDK environment, then run from the monorepo root. See building for general build prerequisites.

    source .venv-therock/bin/activate

mkdir -p "${fi_corpus_dir}"
fi_corpus_source=https://raw.githubusercontent.com/ROCm/rocjitsu-test-corpus/c5e3c38464d7440ef7dc977ed95419d7544afe50/corpus/race/kernels
curl --fail --location "${fi_corpus_source}/fa_barrier_epoch.hip" --output "${fi_corpus_dir}/fa_barrier_epoch.hip"
curl --fail --location "${fi_corpus_source}/utils.hpp" --output "${fi_corpus_dir}/utils.hpp"
rocjitsu_rocm_root=$(rocm-sdk path --root)
"${rocjitsu_rocm_root}/bin/amdclang++" -x hip --offload-arch=gfx1250 --cuda-device-only -O2 -mcode-object-version=5 -c "${fi_corpus_dir}/fa_barrier_epoch.hip" -o "${fi_corpus_dir}/fa_barrier_epoch.bundle"

sha256sum "${fi_corpus_dir}/fa_barrier_epoch.hip" "${fi_corpus_dir}/utils.hpp" "${fi_corpus_dir}/fa_barrier_epoch.hsaco"

    Command-line usage¶

    The mutation library and CLI are included in the normal build. Host integration tests require BUILD_TESTING=ON; the mutation tooling does not require the ConSan components. From the checkout configured as described in Building, build the executable and host integration tests:

    cmake --build emulation/rocjitsu/build --target rj_code_mutate rocjitsu_fault_mutation_cli_tests
emulation/rocjitsu/build/tools/rj_code_mutate --help
emulation/rocjitsu/build/tools/rj_code_mutate --capabilities

    List complete logical barriers for one exact kernel entry, then create a new mutant file. DropBarrier is the default kind:

    emulation/rocjitsu/build/tools/rj_code_mutate \
  --input original.hsaco --kernel my_kernel --list
emulation/rocjitsu/build/tools/rj_code_mutate \
  --input original.hsaco --kernel my_kernel --kind DropBarrier \
  --ordinal 0 --output mutant.hsaco

    The --address-vgpr argument is the encoded 8-bit selector, not a physical VGPR number. Listing reports address_bank; for gfx1250/gfx1251, allocation is checked for 256 * address_bank + address-vgpr. The caller must initialize that full VGPR with the intended runtime address: bank 1 with selector 6 reads v262, so initialize v262. The mutation preserves the bank and does not initialize register values.

    To list the supported LDS instructions in a gfx1100, gfx1200 or gfx1201 wave32 or wave64 kernel and mutate one, choose an address register whose runtime value the caller has initialized. Here v6 is an example only: it must differ from the selected instruction's address register and fall within the kernel descriptor's allocated VGPR window.

    emulation/rocjitsu/build/tools/rj_code_mutate \
  --input original.hsaco --kernel my_kernel --kind LdsWrongAddress --list
emulation/rocjitsu/build/tools/rj_code_mutate \
  --input original.hsaco --kernel my_kernel --kind LdsWrongAddress \
  --ordinal 0 --address-vgpr 6 --output lds-mutant.hsaco

    Alternatively, copy an exact offset from that listing into lds_exact and use it in place of the ordinal. An invalid exact offset never falls back:

    emulation/rocjitsu/build/tools/rj_code_mutate \
  --input original.hsaco --kernel my_kernel --kind LdsWrongAddress \
  --exact "$lds_exact" --address-vgpr 6 --output lds-exact-mutant.hsaco

    The equivalent library flow retains the context for discovery, selection, and application. Handle the returned typed error at each failure; on success, result.value().image owns the mutant ELF:

    #include "rocjitsu/code/patch/fault_injection/lds_wrong_address.h"

using namespace rocjitsu;

void mutate_lds(std::span<const uint8_t> image) {
  FaultMutationContext context(image);
  FaultMutationError error;
  FailureOr<LdsInventory> inventory = discover_lds_wrong_address(context, "my_kernel", error);
  if (inventory.failed())
    return; // Handle error.
  LdsSelector selector = {.exact = std::nullopt, .ordinal = 0};
  FailureOr<LdsSelection> selection = select_lds_wrong_address(inventory.value(), selector, error);
  if (selection.failed())
    return; // Handle error.
  FailureOr<LdsResult> result = apply_lds_wrong_address(context, selection.value(), 6u, error);
  if (result.failed())
    return; // Handle error, including an unallocated or unchanged v6.
  // Consume result.value().image before leaving this example.
}

    To select an exact library handle instead, put a previously obtained LdsSelection in LdsSelector::exact and call select_lds_wrong_address on an inventory from the same context and entry. Exact takes precedence over the ordinal; a foreign or expired handle fails without fallback.

    For atomics, list the exact kernel's complete inventory first:

    emulation/rocjitsu/build/tools/rj_code_mutate \
  --input original.hsaco --kernel my_kernel --kind AtomicWrongAddress --list

    For example, a gfx1201 input containing an eight-byte ds_consume followed by a twelve-byte global_atomic_add_u64 with an immediate offset of zero can produce the following abbreviated listing. All coordinates are relative to pristine .text:

    ordinal=0 exact=0 size=8 byte_offset=unknown address_supported=0 ... form=ds_consume ...
ordinal=1 exact=8 size=12 byte_offset=0 address_supported=1 ... form=global_atomic_add_u64 ...

    The DS atomic occupies ordinal zero even though this recipe cannot mutate it. Copy exact=8 from the row with address_supported=1 and supply an eight-byte delta to preserve the selected 64-bit atomic's natural alignment:

    emulation/rocjitsu/build/tools/rj_code_mutate \
  --input original.hsaco --kernel my_kernel --kind AtomicWrongAddress \
  --exact 8 --address-delta 8 --output atomic-mutant.hsaco

    The selected immediate changes from 0 to 8. --address-delta 4 is rejected with code=InvalidParameters before output creation for this 64-bit operation; 32-bit atomics accept a delta of four bytes. Selecting --exact 0 fails with code=UnsupportedForm, including when --ordinal 1 is also supplied. An exact selection never falls back to the ordinal. Adding a future DS address recipe will not renumber the global atomic.

    For a gfx1250 Drop mutant that meets ConSan's native LDS admission, fresh preparation consumes mutant.hsaco as its new original image:

    emulation/rocjitsu/build/tools/rj_consan_prepare \
  mutant.hsaco gfx1250 my_kernel mutant-artifact

    Preparation requires RJ_BUILD_CONSAN_COMPILER=ON. Use the new artifact when executing the workload with mutant.hsaco, then capture and analyze normally. See the ConSan mutation workflow for fresh artifact and capture bindings and links to the existing execution/analysis steps.

    --kernel requires the exact descriptor-derived spelling. After shared image analysis succeeds, an unknown name reports the descriptor entries in its diagnostic. Those names do not promise that each entry passes the selected recipe's qualification.

    For DropBarrier, each listing line includes the zero-based logical ordinal, exact first-member byte offset relative to .text, concrete target, section index, form, ID, scope, and ordered members=offset:size,.... A singleton has one member; a split pair has two. LdsWrongAddress listing lines contain ordinal, the instruction's .text-relative exact byte offset, its original address_vgpr, address_bank, target, form, affected_owners, and one owner=name:entry_offset:descriptor_file_offset field for every affected kernel. AtomicWrongAddress listing lines contain ordinal, .text-relative exact, instruction size, byte_offset (or unknown), address_supported, target, form and the same affected-owner fields. address_supported=1 describes the instruction's recipe, not whether any particular delta is aligned or in range. The mutation summary reports that same source-coordinate owner set. These fields do not claim per-dispatch isolation. Coordinates describe only this input and exact entry; they are not reusable handles for another image or legacy physical indices.

    Drop emission redirects each selected member through a NOP trampoline. LDS and atomic emission redirect the selected instruction through a trampoline containing the replacement instruction. The mutant's text and ELF layout can grow, and descriptor-relative entry fields can change. Reparse the output and list its sites again before selecting another mutation.

    Drop discovery rejects trap-handler forms (-2 on RDNA4/CDNA5 and -4 on CDNA5) instead of assigning them a logical ordinal, including when an admitted user barrier follows them. CDNA5 cluster ID -3 remains admitted subject to the dispatch assumptions described above; listing or mutation does not establish that cluster semantics are active.

    Use --exact TEXT-OFFSET to resolve that coordinate into a context-bound library selection. Exact takes precedence over --ordinal, including an out-of-range ordinal; invalid exact requests fail without fallback. Without either selector, ordinal zero selects the first complete barrier, supported LDS instruction, or atomic site in source order. The first atomic can be unsupported. Numbers accept unsigned decimal or 0x hexadecimal. --target gfx1250, if supplied, asserts the parsed identity and never selects a different decoder. Input ABI and wave admission are the library's shared DBI checks, without another CLI version gate.

    The input must be a regular extracted code-object file of 1 through 256 MiB. The CLI refuses host executables, bundles, archives, relocatable objects, and other inputs rejected by the library. Output creation is exclusive: existing files, directories, symlinks and hard links (including input aliases) are refused. There is no overwrite flag. A failed write or close removes the incomplete new output. This is single-file I/O, without a multi-file publication protocol or a crash-durability guarantee.

    Exit status is 0 for successful listing/mutation/help/capabilities, 2 for argument, read, admission, selection or mutation errors, and 3 for output I/O errors. All successful stdout paths flush and check the stream. A completed mutant file remains if writing its subsequent assumptions or summary fails; status 3 does not guarantee that no output file exists. The executable ignores SIGPIPE and SIGXFSZ where available so closed pipes and file-size limits reach these I/O checks and incomplete-file cleanup, regardless of the caller's signal dispositions.

    Diagnostics go to stderr. Discovery, selection and mutation failures preserve the library's typed error as code=NAME before the explanatory message. The code names are BadIdentity, UnsupportedTarget, UnsupportedForm, AmbiguousSelection, IncompleteSelection, InvalidParameters, ValidationFailure, NoCandidates and OrdinalOutOfRange. Runners can classify these errors without matching the English message; argument/read diagnostics have no typed library code. Library error offsets do not encode whether a location is present, so those diagnostic prefixes omit the numeric field. An invalid --exact request has an explicitly known coordinate and reports code=InvalidParameters offset=N, including when the requested .text byte coordinate is zero. Such requests never fall back to an ordinal.

    Successful mutation prints the kind, concrete target, exact coordinate, logical count and output byte count to stdout. Drop also reports the member count and prints returned library assumptions to stderr, prefixed by rj_code_mutate: assumption:. These include convergence and execution limits and the clustered dispatch requirement when applicable. Failure to write Drop assumptions returns status 3 before printing a success summary. LDS reports its replacement address_vgpr; its runtime preconditions are described above. The atomic summary reports address_delta in bytes and the affected-owner set. The CLI emits only the mutant file and does not load HSA or a capture plugin. Mutation success and the capability listing make no execution or detector qualification claim.
