================================================================================
THE BUG
================================================================================

The --rebase flag was not correctly displaying rebased memory addresses in the
decoded output. Instead of showing the rebased addresses in a human-readable
decoded format, it was only outputting the rebased packets as hex strings,
requiring a two-step process to see the results.

SYMPTOM:
When running:
  echo "<packet>" | ./pm4_decoder --rebase 0x0

The tool would:
1. Apply rebasing to the packet (✓ correctly)
2. Output the modified packet as HEX to stdout (✗ not user-friendly)
3. Require piping to another ./pm4_decoder call to see decoded output

This made the --rebase flag impractical for interactive use and required
external scripts to work around the limitation.

EVIDENCE:
From test_results.txt:
  "BUG: pm4_decoder not producing decoded output (only echoing hex)
   CAUSE: Script was using --rebase flag, which only outputs rebased hex,
          not decoded packets
   FIX: Removed --rebase flag from subprocess call"

From compare_packets.py line 169:
  "# Note: Not using --rebase because that mode only outputs hex, not
   decoded packets"

================================================================================
THE FIX
================================================================================

Modified the process_packet_string_rebase() function to:
1. Apply rebasing to all packets (unchanged - already working)
2. DECODE and DISPLAY the rebased packets (NEW)
3. Remove hex output mode (no longer needed)

CODE CHANGES:
File: pm4_decoder.c
Function: process_packet_string_rebase()

BEFORE:
  /* Apply rebasing to this packet */
  rebase_pm4_packet(&dwords[offset], header.size_dwords);

  offset += header.size_dwords;
  remaining -= header.size_dwords;
}

/* Output the modified hex string */
dwords_to_hex_string(dwords, (size_t)num_dwords);
printf("\n");

AFTER:
  /* Apply rebasing to this packet */
  rebase_pm4_packet(&dwords[offset], header.size_dwords);

  /* Decode and display the rebased packet */
  decode_pm4_packet(&dwords[offset], header.size_dwords);

  offset += header.size_dwords;
  remaining -= header.size_dwords;
  packet_count++;

  if (remaining > 0) {
      printf("---\n"); /* Separator between packets */
  }
}

RESULT:
The --rebase flag now provides immediate, human-readable decoded output showing
the rebased addresses directly, making it suitable for interactive use.

================================================================================
REBASE ALGORITHM (UNCHANGED)
================================================================================

The rebasing algorithm itself was already working correctly and remains
unchanged:

1. On first COPY_DATA packet encountered:
   - Extract destination address from dwords[4:5]
   - Store as original_base
   - Mark base_found = true

2. For each subsequent COPY_DATA packet:
   - Extract destination address
   - Calculate offset = current_addr - original_base
   - Calculate new_addr = new_base + offset
   - Update packet dwords[4:5] with new_addr

3. For ACQUIRE_MEM packets:
   - Extract address from dwords[4:5] (stored >> 8 bits)
   - Shift left 8 to get actual address
   - Calculate offset from original_base
   - Calculate new_addr = new_base + offset
   - Shift right 8 and store back in dwords[4:5]

The bug was NOT in the rebasing logic itself, but in the OUTPUT format.
