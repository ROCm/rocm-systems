PROBLEM STATEMENT
================================================================================

SQ event packets were not matching the reference implementation. Packet
comparison showed differences in:
1. SET_SH_REG packet for compute_perfcount_enable (incorrect register address)
2. Missing GRBM broadcast packet after SQ_PERFCOUNTER_CTRL2 write
3. Additional double-subtraction issues found in counter configuration

================================================================================
ROOT CAUSE ANALYSIS
================================================================================

Issue 1: Double Subtraction in PM4 Packet Functions
----------------------------------------------------
Several PM4 packet append functions (pm4_append_set_uconfig_reg,
pm4_append_write_sh_reg) already handle address space offset calculations
internally. The code was incorrectly performing these subtractions before
calling the functions, resulting in double subtraction and incorrect register
addresses in the generated packets.

Affected locations:
- Line 86:  reg_info->select_addr
- Line 109: reg_info->control_addr
- Line 159: arch->control_regs.sq_perfcounter_ctrl2
- Line 179: arch->control_regs.compute_perfcount_enable

Issue 2: Missing GRBM Broadcast Reset
--------------------------------------
After writing SQ_PERFCOUNTER_CTRL2, the GRBM_GFX_INDEX register needs to be
reset to broadcast mode before configuring individual counters. This ensures
that counter configurations are properly broadcast to all shader engines.

Location: After line 162 (after SQ_PERFCOUNTER_CTRL2 write)

================================================================================
FIXES APPLIED
================================================================================

Fix 1: Remove Double Subtraction (4 locations)
-----------------------------------------------

A) generate_counter_config() - Line 86:
   BEFORE: reg_info->select_addr - arch->control_regs.uconfig_space_start
   AFTER:  reg_info->select_addr

B) generate_counter_config() - Line 109:
   BEFORE: reg_info->control_addr - arch->control_regs.uconfig_space_start
   AFTER:  reg_info->control_addr

C) generate_start_packet() - Line 159:
   BEFORE: arch->control_regs.sq_perfcounter_ctrl2 -
           arch->control_regs.uconfig_space_start
   AFTER:  arch->control_regs.sq_perfcounter_ctrl2

D) generate_start_packet() - Line 179:
   BEFORE: arch->control_regs.compute_perfcount_enable -
           arch->control_regs.persistent_space_start
   AFTER:  arch->control_regs.compute_perfcount_enable


Fix 2: Add GRBM Broadcast Reset (Lines 164-167)
------------------------------------------------

ADDED after SQ_PERFCOUNTER_CTRL2 write:

    /* Reset GRBM_GFX_INDEX to broadcast before configuring counters */
    ret = generate_grbm_broadcast(buffer, arch);
    if (ret < 0)
      return ret;

This ensures GRBM_GFX_INDEX is in broadcast mode before writing counter
configuration registers.
