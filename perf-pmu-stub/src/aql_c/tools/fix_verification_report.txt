Fix 1: Remove Double Subtraction in SET_SH_REG (Line 178-179)
--------------------------------------------------------------
Location: generate_start_packet() function

BEFORE:
  ret = pm4_append_write_sh_reg(buffer,
                                arch->control_regs.compute_perfcount_enable -
                                    arch->control_regs.persistent_space_start,
                                0x1, /* enable */
                                0, 0);

AFTER:
  ret = pm4_append_write_sh_reg(buffer,
                                arch->control_regs.compute_perfcount_enable,
                                0x1, /* enable */
                                0, 0);

Rationale:
- The pm4_append_write_sh_reg() function already handles the offset calculation
  internally by subtracting persistent_space_start
- Double subtraction was causing incorrect register addresses
- This was causing mismatches in the SET_SH_REG packet for compute_perfcount_enable


Fix 2: Add GRBM Broadcast Before Counter Config (Line 164-167)
---------------------------------------------------------------
Location: generate_start_packet() function, after SQ_PERFCOUNTER_CTRL2 write

ADDED CODE:
  if (has_sq_counters) {
    uint32_t sq_ctrl2_value =
        (1U << 0) | (0xFFFFU << 1); /* force_en | vmid_en */
    ret = pm4_append_set_uconfig_reg(
        buffer,
        arch->control_regs.sq_perfcounter_ctrl2, /* mmSQ_PERFCOUNTER_CTRL2 */
        sq_ctrl2_value);
    if (ret < 0)
      return ret;

    /* Reset GRBM_GFX_INDEX to broadcast before configuring counters */
    ret = generate_grbm_broadcast(buffer, arch);
    if (ret < 0)
      return ret;
  }

Rationale:
- After writing SQ_PERFCOUNTER_CTRL2, GRBM_GFX_INDEX needs to be reset to
  broadcast mode before configuring individual counters
- Missing GRBM broadcast was causing packet sequence mismatch
- This ensures counter configuration is broadcast to all shader engines
