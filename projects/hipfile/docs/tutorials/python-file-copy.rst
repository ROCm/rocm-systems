===================================
Python file copy through GPU memory
===================================

This tutorial walks through ``python/main.py``, a complete script that reads a
file from storage into GPU memory, writes that GPU buffer back to a second
file, and then verifies the copy with SHA-256 hashes. It demonstrates every
major class in the hipFile Python API: ``Driver``, ``FileHandle``, ``Buffer``,
and the ``hipMalloc`` and ``hipFree`` helpers.

You would use this pattern whenever you need to move data through GPU memory
from Python — for example, loading training data directly into device memory
before a HIP kernel processes it, or staging checkpoint writes without
round-tripping through CPU buffers.

Prerequisites
*************

- AMD ROCm with the HIP runtime installed (``libamdhip64.so`` must be loadable).
- The hipFile Python package (``hipfile``) built and installed.
  See :doc:`/install/install` for build instructions.
- An input file on a filesystem that supports ``O_DIRECT`` (ext4 or xfs).
  The script hardcodes paths under ``/mnt/ais/ext4/``; adjust them for your
  environment.

Complete code
*************

The listing below reproduces ``python/main.py``:

.. code-block:: python

   import hashlib
   import os
   import pathlib

   from hipfile.hipMalloc import hipFree, hipMalloc

   from hipfile import (
       Driver,
       FileHandle,
       Buffer,
       FileHandleType,
       get_version,
   )

   hipfile_version = get_version()

   input_path = pathlib.Path("/mnt/ais/ext4/random_2MiB.bin")
   output_path = pathlib.Path("/mnt/ais/ext4/output.bin")

   print(f"hipFile Version: {hipfile_version}")
   print(f"Driver Use Count Before: {Driver.use_count()}")

   # Max to a 2GiB - 4KiB Buffer
   size = min(input_path.stat().st_size, 2 * 1024 * 1024 * 1024 - 4 * 1024)
   buffer = hipMalloc(size)
   buffer_ptr = buffer.value
   print(f"Buffer located at: {buffer_ptr} | {hex(buffer_ptr)}")

   with Driver() as hipfile_driver:
       print(f"Driver Use Count After: {hipfile_driver.use_count()}")
       with Buffer.from_ctypes_void_p(buffer, size, 0) as registered_buffer:
           with FileHandle(
               input_path,
               os.O_RDWR | os.O_DIRECT | os.O_CREAT,
               handle_type=FileHandleType.OPAQUE_FD,
           ) as fh_input:
               with FileHandle(
                   output_path, os.O_RDWR | os.O_DIRECT | os.O_CREAT | os.O_TRUNC
               ) as fh_output:
                   print(f"Transferring {size} bytes...")
                   bytes_read = fh_input.read(registered_buffer, size, 0, 0)
                   print(f"Bytes Read: {bytes_read}")
                   bytes_written = fh_output.write(registered_buffer, size, 0, 0)
                   print(f"Bytes Written: {bytes_written}")

   hipFree(buffer)

   with open(input_path, "br") as file_in:
       hash_in = hashlib.sha256()
       chunk = file_in.read(1 * 1024 * 1024)
       while len(chunk) != 0:
           hash_in.update(chunk)
           chunk = file_in.read(1 * 1024 * 1024)
       print(f"Input File Hash: {hash_in.hexdigest()}")

   with open(output_path, "br") as file_out:
       hash_out = hashlib.sha256()
       chunk = file_out.read(1 * 1024 * 1024)
       while len(chunk) != 0:
           hash_out.update(chunk)
           chunk = file_out.read(1 * 1024 * 1024)
       print(f"Output File Hash: {hash_out.hexdigest()}")

Step-by-step walkthrough
************************

Query the library version
-------------------------

.. code-block:: python

   from hipfile import get_version
   hipfile_version = get_version()

``get_version`` returns a ``(major, minor, patch)`` tuple by calling
``hipFileGetVersion`` through the Cython layer. It raises
``HipFileException`` if the call fails.

Allocate GPU memory with ``hipMalloc``
--------------------------------------

.. code-block:: python

   from hipfile.hipMalloc import hipFree, hipMalloc

   size = min(input_path.stat().st_size, 2 * 1024 * 1024 * 1024 - 4 * 1024)
   buffer = hipMalloc(size)

The ``hipMalloc`` helper in ``python/hipfile/hipMalloc.py`` loads ``libamdhip64.so``
through ``ctypes`` and calls the HIP runtime's ``hipMalloc``. It returns a
``ctypes.c_void_p`` pointing to device memory. The transfer size is capped at
2 GiB − 4 KiB because that is the maximum single-IO size set by the Linux
kernel.

``hipMalloc`` raises ``RuntimeError`` if the HIP runtime reports an error.

Open the hipFile driver with the ``Driver`` context manager
-----------------------------------------------------------

.. code-block:: python

   with Driver() as hipfile_driver:
       ...

``Driver`` wraps the reference-counted ``hipFileDriverOpen`` and
``hipFileDriverClose`` calls. Entering the ``with`` block calls ``open()``;
exiting calls ``close()``. The static method ``Driver.use_count()`` returns the
current driver reference count via ``hipFileUseCount``.

Register the GPU buffer with ``Buffer.from_ctypes_void_p``
----------------------------------------------------------

.. code-block:: python

   with Buffer.from_ctypes_void_p(buffer, size, 0) as registered_buffer:
       ...

``Buffer`` does **not** own the underlying GPU allocation — it only manages the
hipFile registration lifetime. Entering the ``with`` block calls
``hipFileBufRegister``; exiting calls ``hipFileBufDeregister``. This separation
is intentional: the GPU memory was allocated by ``hipMalloc`` and must be freed
separately by ``hipFree``.

``from_ctypes_void_p`` is a class method that accepts a ``ctypes.c_void_p``, a
byte length, and registration flags (pass ``0`` for default behavior). It
raises ``ValueError`` if the pointer is null.

Open files with ``FileHandle``
------------------------------

.. code-block:: python

   with FileHandle(
       input_path,
       os.O_RDWR | os.O_DIRECT | os.O_CREAT,
       handle_type=FileHandleType.OPAQUE_FD,
   ) as fh_input:
       with FileHandle(
           output_path, os.O_RDWR | os.O_DIRECT | os.O_CREAT | os.O_TRUNC
       ) as fh_output:
           ...

Each ``FileHandle`` wraps ``os.open`` together with ``hipFileHandleRegister``.
The ``os.O_RDWR | os.O_DIRECT`` flags are important: ``O_DIRECT`` is required
for hipFile's GPU-direct fast path. Including ``os.O_CREAT`` creates the file
if it does not exist; ``os.O_TRUNC`` on the output path removes any previous
content. The default ``handle_type`` is ``FileHandleType.OPAQUE_FD`` (a POSIX
file descriptor). The default ``mode`` is ``0o644``.

On context-manager exit, ``FileHandle.close()`` deregisters the hipFile handle
and closes the POSIX file descriptor.

Read and write through GPU memory
---------------------------------

.. code-block:: python

   bytes_read = fh_input.read(registered_buffer, size, 0, 0)
   bytes_written = fh_output.write(registered_buffer, size, 0, 0)

``FileHandle.read`` calls ``hipFileRead``, reading ``size`` bytes from
``file_offset=0`` into the GPU buffer at ``buffer_offset=0``. It returns the
number of bytes read.

``FileHandle.write`` calls ``hipFileWrite``, writing the same range from the
GPU buffer into the output file.

Both methods can raise:

- ``RuntimeError`` if the file handle is not open.
- ``OSError`` (wrapping ``errno``) on a system-level IO error.
- ``HipFileException`` on a hipFile or HIP driver error.

Free GPU memory
---------------

.. code-block:: python

   hipFree(buffer)

After the ``Driver`` and ``Buffer`` context managers have exited (closing the
driver and deregistering the buffer), the GPU allocation is freed by calling
``hipFree``. This is separate from ``Buffer`` cleanup because ``Buffer`` does
not own the allocation.

SHA-256 hash verification
-------------------------

.. code-block:: python

   with open(input_path, "br") as file_in:
       hash_in = hashlib.sha256()
       chunk = file_in.read(1 * 1024 * 1024)
       while len(chunk) != 0:
           hash_in.update(chunk)
           chunk = file_in.read(1 * 1024 * 1024)
       print(f"Input File Hash: {hash_in.hexdigest()}")

The script reads both the input and output files in 1 MiB chunks through
standard Python IO (no GPU involvement) and computes SHA-256 digests. If the
copy succeeded, the two hex digests are identical.

Error handling with ``HipFileException``
****************************************

Every hipFile Python method that wraps a C API call checks the returned error
tuple. When the ``hipFileOpError_t`` component is non-zero, a
``HipFileException`` is raised. The exception carries two properties:

- ``hipfile_err`` — the ``hipFileOpError_t`` integer value.
- ``hip_err`` — the ``hipError_t`` value from the HIP runtime, meaningful only
  when ``hipfile_err`` equals ``OpError.HIP_DRIVER_ERROR``.

Its ``__str__`` method calls ``hipFileGetOpErrorString`` to produce a
human-readable message.

You can catch it like any other exception:

.. code-block:: python

   from hipfile import HipFileException

   try:
       fh.read(buf, size, 0, 0)
   except HipFileException as e:
       print(f"hipFile error {e.hipfile_err}: {e}")
