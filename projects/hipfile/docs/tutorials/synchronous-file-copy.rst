==============================================
Synchronous GPU-mediated file copy (``aiscp``)
==============================================

This tutorial walks through the ``aiscp`` example program, a minimal file-copy
utility that transfers data from a source file to a destination file by routing
every byte through GPU memory. The example demonstrates the core synchronous
hipFile workflow: opening files with ``O_DIRECT``, registering them with
hipFile, allocating a GPU buffer, and copying data in a chunk loop using
``hipFileRead`` and ``hipFileWrite``.

Use this pattern when you need to move bulk data between storage and GPU
memory without staging through CPU DRAM. Typical scenarios include
loading training data for AI workloads and checkpointing simulation
state.

Prerequisites
*************

- AMD ROCm installed with HIP runtime available.
- hipFile built and installed (see :doc:`/install/install`).
- A GPU visible to the HIP runtime.
- Source and destination paths on a filesystem that supports ``O_DIRECT``
  (for example, ext4 with ordered journaling, or XFS). The hipFile fast path
  requires ``O_DIRECT``; see :doc:`/conceptual/io-backends` for details on
  backend selection.

Step 1 – define the chunk size limit
************************************

``AISCP_CHUNK_SIZE`` is set to ``0x7ffff000`` (approximately 2 GiB minus one
page). This value matches the Linux kernel's ``MAX_RW_COUNT``, which is the
largest transfer a single ``read`` or ``write`` system call can process. Each
iteration of the copy loop transfers at most this many bytes.

.. code-block:: cpp

   #define AISCP_CHUNK_SIZE 0x7ffff000LU

You can override this value at compile time if your workload benefits from
smaller chunks—for example, to reduce the GPU buffer footprint.

Step 2 – open and register files
********************************

Both the source and destination files are opened with ``O_DIRECT`` so that
hipFile can use the GPU-direct fast path. Each file descriptor is then
wrapped in a ``hipFileDescr_t`` and registered with ``hipFileHandleRegister``,
which returns an opaque ``hipFileHandle_t`` used for all subsequent IO calls.

.. code-block:: cpp

   static int
   open_file(const char *path, int flags, mode_t mode, int *fd, hipFileHandle_t *handle)
   {
       hipFileError_t hipfile_err;
       hipFileDescr_t descr;

       *fd = open(path, flags | O_DIRECT, mode);
       if (-1 == *fd) {
           fprintf(stderr, "Could not open %s (%s)\n", path, strerror(errno));
           return 1;
       }

       descr.type      = hipFileHandleTypeOpaqueFD;
       descr.handle.fd = *fd;

       hipfile_err = hipFileHandleRegister(handle, &descr);
       if (hipFileSuccess != hipfile_err.err) {
           fprintf(stderr, "Could not register %s (%s)\n", path,
                   hipFileGetOpErrorString(hipfile_err.err));
           close(*fd);
           return 1;
       }

       return 0;
   }

Key points:

- ``hipFileDescr_t.type`` is set to ``hipFileHandleTypeOpaqueFD`` for a POSIX
  file descriptor.
- ``hipFileHandleRegister`` initializes the hipFile driver automatically if it
  has not been opened with ``hipFileDriverOpen``. For more on this lifecycle,
  see :doc:`/conceptual/registration-lifecycle`.
- The error check compares ``hipfile_err.err`` against ``hipFileSuccess`` and
  uses ``hipFileGetOpErrorString`` to produce a human-readable message.

The destination file is opened with ``O_WRONLY | O_CREAT``, and the source
file is opened with ``O_RDONLY``:

.. code-block:: cpp

   if (open_file(dst_path, O_WRONLY | O_CREAT, S_IWUSR | S_IRUSR | S_IRGRP | S_IROTH,
                 &dst_fd, &dst_handle)) {
       goto program_exit;
   }

   if (open_file(src_path, O_RDONLY, 0, &src_fd, &src_handle)) {
       goto close_dst;
   }

Step 3 – allocate a GPU buffer
******************************

A device buffer is allocated with ``hipMalloc``. Its size is the smaller of the
source file size and ``AISCP_CHUNK_SIZE``, rounded up to the filesystem block
size so that ``O_DIRECT`` alignment requirements are satisfied.

.. code-block:: cpp

   buffer_size = align_up(std::min(file_size, AISCP_CHUNK_SIZE), block_size);
   hip_err     = hipMalloc(&devbuf, buffer_size);
   if (hipSuccess != hip_err) {
       fprintf(stderr, "Could not allocate device buffer (%d)", hip_err);
       goto close_src;
   }

The ``align_up`` helper rounds a value up to the next multiple of a
power-of-two alignment:

.. code-block:: cpp

   static inline size_t
   align_up(size_t value, size_t align)
   {
       return (value + align - 1) & ~(align - 1);
   }

Note that ``aiscp`` does **not** call ``hipFileBufRegister``. Buffer
registration is optional. When a buffer is not explicitly registered,
hipFile uses an internal bounce buffer. Registering the buffer with
``hipFileBufRegister`` can improve throughput for workloads that perform
many IO operations on the same buffer. See
:doc:`/reference/api-file-handle-and-buffer` for the full API reference.

Step 4 – chunk-loop: read and write
***********************************

The core of the copy is a ``do … while`` loop that reads from the source into
the GPU buffer, then writes from the GPU buffer to the destination. The
``file_offset`` advances by the number of bytes read each iteration.

.. code-block:: cpp

   do {
       nread = hipFileRead(src_handle, devbuf, buffer_size, file_offset, 0);
       if (nread < 0) {
           fprintf(stderr, "Could not read from %s (%zd) (%s)\n", src_path, nread,
                   IS_HIPFILE_ERR(nread) ? HIPFILE_ERRSTR(nread) : strerror(errno));
           goto free_devbuf;
       }

       nwrite = 0;
       while (nwrite < nread) {
           nbytes =
               hipFileWrite(dst_handle, devbuf, align_up(static_cast<size_t>(nread - nwrite), block_size),
                            file_offset + nwrite, nwrite);
           if (nbytes < 0) {
               fprintf(stderr, "Could not write to %s (%zd) (%s)\n", dst_path, nbytes,
                       IS_HIPFILE_ERR(nbytes) ? HIPFILE_ERRSTR(nbytes) : strerror(errno));
               goto free_devbuf;
           }
           nwrite += nbytes;
       }
       file_offset += nread;
   } while (nread > 0);

``hipFileRead`` and ``hipFileWrite`` return:

- A non-negative count of bytes transferred on success.
- ``-1`` for a POSIX system error (check ``errno``).
- A negative hipFile error code (the negated ``hipFileOpError_t`` value).

Error-checking pattern
^^^^^^^^^^^^^^^^^^^^^^

The example classifies negative return values with the ``IS_HIPFILE_ERR``
macro. If it returns true, ``HIPFILE_ERRSTR`` converts the code to a string.
Otherwise, the error is a POSIX error and ``strerror(errno)`` provides the
description.

.. code-block:: cpp

   IS_HIPFILE_ERR(nread) ? HIPFILE_ERRSTR(nread) : strerror(errno)

The inner ``while`` loop handles partial writes. Each write is
block-aligned with ``align_up`` and uses a non-zero ``buffer_offset``
(``nwrite``) so the write starts from the correct position inside the GPU
buffer.

Step 5 – truncate to exact size
*******************************

Because ``O_DIRECT`` requires block-aligned transfer sizes, the last write
might extend the destination file beyond the true file size. ``ftruncate``
trims the file to the exact source size.

.. code-block:: cpp

   if (-1 == ftruncate(dst_fd, static_cast<off_t>(file_size))) {
       fprintf(stderr, "Could not truncate %s (%zu) (%s)\n", dst_path, file_size,
               strerror(errno));
   }

Step 6 – cleanup
****************

Cleanup proceeds in reverse order of acquisition: free the GPU buffer with
``hipFree``, deregister and close the source file, then deregister and close
the destination file.

``hipFileHandleDeregister`` takes the ``hipFileHandle_t`` returned from
registration and releases hipFile's internal tracking for that file.
The underlying POSIX file descriptor is then closed separately with
``close``.

Running the example
*******************

.. code-block:: console

   $ ./aiscp /path/to/source_file /path/to/dest_file

Both paths should reside on a filesystem that supports ``O_DIRECT``. If the
source file is empty, the program exits successfully without performing any IO.
