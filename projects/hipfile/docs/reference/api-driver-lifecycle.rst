==============================
Driver lifecycle API reference
==============================

*Declared in:* ``include/hipfile.h``

The hipFile driver lifecycle API manages initialization and shutdown of the GPU IO library state. The driver uses reference counting: each call to ``hipFileDriverOpen`` increments the count and each call to ``hipFileDriverClose`` decrements it. When the count transitions from zero to one the library state is initialized, and when it transitions from one to zero the state is destroyed.

Calling ``hipFileDriverOpen`` explicitly is optional. The first call to ``hipFileHandleRegister`` or ``hipFileBufRegister`` triggers library initialization and increments the reference count automatically. The library state is also destroyed at program exit, so explicitly closing the driver is not required.

For a conceptual discussion of the registration and lifecycle model, see :doc:`/conceptual/registration-lifecycle`.

Functions
*********

``hipFileDriverOpen``
---------------------

Initialize the GPU IO driver for this process.

.. code-block:: c

   HIPFILE_API hipFileError_t hipFileDriverOpen(void);

Each call increments the library's reference count. If the count transitions from zero to one, the library's state is initialized.

:returns: ``hipFileError_t`` indicating the result of the operation.

``hipFileDriverClose``
----------------------

Close the GPU IO driver for this process.

.. code-block:: c

   HIPFILE_API hipFileError_t hipFileDriverClose(void);

Each call decrements the library's reference count. If the count transitions from one to zero, the library's state is destroyed. Explicitly closing the library is not required; the state is destroyed automatically at program exit.

:returns: ``hipFileError_t`` indicating the result of the operation.

``hipFileDriverProps_t``
------------------------

GPU IO configuration structure returned by ``hipFileDriverGetProperties``.

.. code-block:: c

   typedef struct hipFileDriverProps {
       struct {
           unsigned major_version;
           unsigned minor_version;
           uint64_t poll_thresh_size;
           uint64_t max_direct_io_size;
           unsigned driver_status_flags;
           unsigned driver_control_flags;
       } nvfs;

       unsigned feature_flags;
       uint64_t max_device_cache_size;
       uint64_t per_buffer_cache_size;
       uint64_t max_device_pinned_mem_size;
       unsigned max_batch_io_count;
       unsigned max_batch_io_timeout_msecs;
   } hipFileDriverProps_t;

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - Field
     - Description
   * - ``nvfs.major_version``
     - Major version of the GPU IO driver
   * - ``nvfs.minor_version``
     - Minor version of the GPU IO driver
   * - ``nvfs.poll_thresh_size``
     - Maximum IO size (in KiB) for which polling is used when poll mode is enabled
   * - ``nvfs.max_direct_io_size``
     - Maximum IO size (in KiB) used by the GPU IO driver
   * - ``nvfs.driver_status_flags``
     - Bitfield that maps to ``hipFileDriverStatusFlags_t``

     - Bitfield that maps to ``hipFileDriverControlFlags_t``
   * - ``feature_flags``
     - Bitfield that maps to ``hipFileFeatureFlags_t``
   * - ``max_device_cache_size``
     - Maximum amount of GPU memory (in KiB) that can be used for bounce buffers
   * - ``per_buffer_cache_size``
     - Amount of GPU memory (in KiB) allocated for each bounce buffer
   * - ``max_device_pinned_mem_size``
     - Maximum amount of GPU memory (in KiB) that can be pinned
   * - ``max_batch_io_count``
     - Maximum number of batch operations that can be submitted at once
   * - ``max_batch_io_timeout_msecs``
     - Timeout (in msec) for a batch operation to complete
