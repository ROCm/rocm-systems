====================================
File handle and buffer API reference
====================================

This page documents the hipFile types and functions for registering file handles
and GPU memory buffers and for performing synchronous read and write operations.
These form the core IO surface of the library.

For an explanation of the registration and deregistration lifecycle, see
:doc:`/conceptual/registration-lifecycle`. For details on how hipFile selects
between the fast-path and fallback IO backends, see
:doc:`/conceptual/io-backends`.

*Declared in:* ``include/hipfile.h``

Data types
**********

``hipFileHandle_t``
-------------------

.. code-block:: c

   typedef void *hipFileHandle_t;

Opaque file handle used by the GPU IO driver and library. Obtained from
``hipFileHandleRegister`` and passed to IO functions such as ``hipFileRead``
and ``hipFileWrite``.

``hipFileFileHandleType_t``
---------------------------

.. code-block:: c

   typedef enum hipFileFileHandleType {
       hipFileHandleTypeOpaqueFD    = 1,
       hipFileHandleTypeOpaqueWin32 = 2,
       hipFileHandleTypeUserspaceFS = 3,
   } hipFileFileHandleType_t;

Identifies the kind of OS file handle stored in a ``hipFileDescr_t``.

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - Enumerator
     - Description
   * - ``hipFileHandleTypeOpaqueFD``
     - POSIX file descriptor
   * - ``hipFileHandleTypeOpaqueWin32``
     - Win32 ``HANDLE`` file handle
   * - ``hipFileHandleTypeUserspaceFS``
     - Userspace RDMA filesystem

``hipFileDescr_t``
------------------

.. code-block:: c

   typedef struct hipFileDescr {
       hipFileFileHandleType_t type;
       union {
           int   fd;
           void *hFile;
       } handle;
       const hipFileFSOps_t *fs_ops;
   } hipFileDescr_t;

Top-level structure for describing a file to register for GPU IO.

.. list-table::
   :header-rows: 1
   :widths: 20 80

   * - Field
     - Description
   * - ``type``
     - Type of file handle being used (see ``hipFileFileHandleType_t``).
   * - ``handle.fd``
     - POSIX file descriptor. Used when ``type`` is ``hipFileHandleTypeOpaqueFD`` or ``hipFileHandleTypeUserspaceFS``.
   * - ``handle.hFile``
     - Win32 ``HANDLE`` file handle. Used when ``type`` is ``hipFileHandleTypeOpaqueWin32``.
   * - ``fs_ops``
     - Pointer to userspace RDMA filesystem operations. Ignored unless ``type`` is ``hipFileHandleTypeUserspaceFS``.

The mapping between ``type`` and the other fields is:

- ``hipFileHandleTypeOpaqueFD`` — ``handle.fd`` non-negative, ``fs_ops`` ignored.
- ``hipFileHandleTypeOpaqueWin32`` — ``handle.hFile`` non-NULL, ``fs_ops`` ignored.
- ``hipFileHandleTypeUserspaceFS`` — ``handle.fd`` non-negative, ``fs_ops`` non-NULL.

``hipFileFSOps_t``
------------------

.. code-block:: c

   typedef struct hipFileFSOps {
       const char *(*fs_type)(void *handle);
       int (*getRDMADeviceList)(void *handle, struct sockaddr **hostaddrs);
       int (*getRDMADevicePriority)(void *handle, char *, size_t, hoff_t,
                                    struct sockaddr *hostaddr);
       ssize_t (*read)(void *handle, char *, size_t, hoff_t, hipFileRDMAInfo_t *);
       ssize_t (*write)(void *handle, const char *, size_t, hoff_t,
                        hipFileRDMAInfo_t *);
   } hipFileFSOps_t;

IO operations for RDMA filesystems. Each field is a function pointer; any
pointer that is ``NULL`` falls back to a default behavior as noted below.

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Function pointer
     - Description
   * - ``fs_type``
     - Return the type of remote filesystem. If ``NULL``, ``fstat`` is used to discover the type.
   * - ``getRDMADeviceList``
     - Get a list of host RDMA addresses. If ``NULL``, any address is used.
   * - ``getRDMADevicePriority``
     - Get the assigned priority of an RDMA device. A return value of ``-1`` indicates no preference.
   * - ``read``
     - Read from the remote filesystem. If ``NULL``, the Linux VFS is used.
   * - ``write``
     - Write to the remote filesystem. If ``NULL``, the Linux VFS is used.

``hipFileRDMAInfo_t``
---------------------

.. code-block:: c

   typedef struct hipFileRDMAInfo {
       int         version;
       int         desc_len;
       const char *desc_str;
   } hipFileRDMAInfo_t;

Userspace RDMA configuration passed to ``hipFileFSOps_t`` read and write
callbacks.

.. list-table::
   :header-rows: 1
   :widths: 20 80

   * - Field
     - Description
   * - ``version``
     - Version of the RDMA API to use.
   * - ``desc_len``
     - Length of the description string.
   * - ``desc_str``
     - Describes the configuration of the RDMA operation.

RDMA characteristic flags
^^^^^^^^^^^^^^^^^^^^^^^^^

.. code-block:: c

   #define HIPFILE_RDMA_REGISTER          1
   #define HIPFILE_RDMA_RELAXED_ORDERING  (1 << 1)

Bitwise flags that describe RDMA characteristics:

- ``HIPFILE_RDMA_REGISTER`` — the RDMA operation is registered.
- ``HIPFILE_RDMA_RELAXED_ORDERING`` — the RDMA operation uses relaxed ordering.

.. note::

   RDMA is not currently supported in hipFile. Setting RDMA options has no
   effect.

File handle registration
************************

``hipFileHandleRegister``
-------------------------

Registers an open file for GPU IO.

.. code-block:: c

   HIPFILE_API hipFileError_t hipFileHandleRegister(hipFileHandle_t *fh,
                                                    hipFileDescr_t *descr);

:param fh: *(out)* Receives the opaque file handle on success.
:param descr: *(in)* Parameters describing the file to register.
:returns: ``hipFileError_t`` indicating success or the error encountered.

.. note::

   If the library has not already been initialized, the first call to
   ``hipFileHandleRegister()`` initializes the library and increments the
   reference count.

``hipFileHandleDeregister``
---------------------------

Deregisters a file from GPU IO.

.. code-block:: c

   HIPFILE_API void hipFileHandleDeregister(hipFileHandle_t fh);

:param fh: *(in)* The file handle to deregister.

Buffer registration
*******************

``hipFileBufRegister``
----------------------

Registers a GPU memory region to be used with GPU IO. The memory region
should be allocated by the caller before being passed to this function.

.. code-block:: c

   HIPFILE_API hipFileError_t hipFileBufRegister(const void *buffer_base,
                                                 size_t length,
                                                 int flags);

:param buffer_base: *(in)* Base pointer of the GPU buffer.
:param length: *(in)* Size of the allocated buffer in bytes.
:param flags: *(in)* Control flags for this buffer.
:returns: ``hipFileError_t`` indicating success or the error encountered.

.. note::

   If the library has not already been initialized, the first call to
   ``hipFileBufRegister()`` initializes the library and increments the
   reference count.

``hipFileBufDeregister``
------------------------

Deregisters a GPU memory region from being used with GPU IO.

.. code-block:: c

   HIPFILE_API hipFileError_t hipFileBufDeregister(const void *buffer_base);

:param buffer_base: *(in)* Base pointer of the GPU buffer to deregister.
:returns: ``hipFileError_t`` indicating success or the error encountered.

Synchronous IO
**************

``hipFileRead``
---------------

Synchronously reads data from a file into a GPU buffer.

.. code-block:: c

   HIPFILE_API ssize_t hipFileRead(hipFileHandle_t fh,
                                   void *buffer_base,
                                   size_t size,
                                   hoff_t file_offset,
                                   hoff_t buffer_offset);

:param fh: *(in)* Registered file handle.
:param buffer_base: *(in)* Base pointer of the GPU buffer.
:param size: *(in)* Number of bytes to read.
:param file_offset: *(in)* Byte offset into the file to read from.
:param buffer_offset: *(in)* Byte offset into the GPU buffer where data is written.
:returns:
   - If >= 0: number of bytes read.
   - If -1: system error (check ``errno`` for the specific error).
   - Otherwise: negative value of the related ``hipFileOpError_t``.

.. note::

   The maximum single IO transfer size is ``0x7ffff000`` bytes
   (2,147,479,552 bytes). This value is derived from the kernel's
   ``MAX_RW_COUNT`` and equals ``INT_MAX`` masked to the system page size.

``hipFileWrite``
----------------

Synchronously writes data from a GPU buffer to a file.

.. code-block:: c

   HIPFILE_API ssize_t hipFileWrite(hipFileHandle_t fh,
                                    const void *buffer_base,
                                    size_t size,
                                    hoff_t file_offset,
                                    hoff_t buffer_offset);

:param fh: *(in)* Registered file handle.
:param buffer_base: *(in)* Base pointer of the GPU buffer.
:param size: *(in)* Number of bytes to write.
:param file_offset: *(in)* Byte offset into the file to write to.
:param buffer_offset: *(in)* Byte offset into the GPU buffer where data is read from.
:returns:
   - If >= 0: number of bytes written.
   - If -1: system error (check ``errno`` for the specific error).
   - Otherwise: negative value of the related ``hipFileOpError_t``.

.. note::

   The maximum single IO transfer size is ``0x7ffff000`` bytes
   (2,147,479,552 bytes). This value is derived from the kernel's
   ``MAX_RW_COUNT`` and equals ``INT_MAX`` masked to the system page size.
