=============================
Asynchronous IO API reference
=============================

.. warning::

   Asynchronous IO is not yet supported on AMD ROCm backends in the current
   release. Calls to the functions documented on this page return the error
   code ``hipFileAsyncNotSupported``. On NVIDIA platforms, these functions
   delegate to the underlying cuFile async API.

The hipFile asynchronous IO surface submits read and write requests onto a
HIP stream so that data transfers between storage and GPU memory can overlap
with kernel execution or other stream work. Before submitting async IO, you
register a HIP stream with ``hipFileStreamRegister``; when async IO on that
stream is no longer needed, you deregister the stream with
``hipFileStreamDeregister``.

For a walkthrough that combines multiple streams with async IO, see
:doc:`/tutorials/async-multistream-io`.

*Declared in:* ``include/hipfile.h``

Stream registration flags
*************************

These preprocessor constants are bitwise flags passed in the ``flags``
parameter of ``hipFileStreamRegister``. They inform the library about
invariants that hold across every submission on the registered stream,
allowing potential per-submission optimization.

``HIPFILE_STREAM_FIXED_BUF_OFFSET``
   Buffer offset is fixed at time of submission. Value: ``1``.

``HIPFILE_STREAM_FIXED_FILE_OFFSET``
   File offset is fixed at time of submission. Value: ``(1 << 1)``.

``HIPFILE_STREAM_FIXED_FILE_SIZE``
   File size is fixed at time of submission. Value: ``(1 << 2)``.

``HIPFILE_STREAM_PAGE_ALIGNED_INPUTS``
   Offsets and size are 4 KiB aligned. Value: ``(1 << 3)``.

``HIPFILE_STREAM_FLAGS_MASK``
   Mask for selecting valid flag bits. Value: ``0xf``.

Combine flags with bitwise OR when more than one invariant applies.

Functions
*********

``hipFileStreamRegister``
-------------------------

Register a HIP stream for asynchronous GPU IO.

.. code-block:: c

   HIPFILE_API hipFileError_t hipFileStreamRegister(hipStream_t stream, unsigned flags);

:param stream: HIP stream to register.
:param flags: Bitwise OR of zero or more stream registration flag constants
   (``HIPFILE_STREAM_FIXED_BUF_OFFSET``, ``HIPFILE_STREAM_FIXED_FILE_OFFSET``,
   ``HIPFILE_STREAM_FIXED_FILE_SIZE``, ``HIPFILE_STREAM_PAGE_ALIGNED_INPUTS``).
   Pass ``0`` if no hints apply.
:returns: ``hipFileError_t`` with ``hipFileSuccess`` on success or an
   appropriate error code on failure.

``hipFileStreamDeregister``
---------------------------

Deregister a stream and free the associated resources.

.. code-block:: c

   HIPFILE_API hipFileError_t hipFileStreamDeregister(hipStream_t stream);

:param stream: HIP stream previously registered with ``hipFileStreamRegister``.
:returns: ``hipFileError_t`` with ``hipFileSuccess`` on success or an
   appropriate error code on failure.

``hipFileReadAsync``
--------------------

Perform an asynchronous read from a file into a GPU buffer on the specified
stream.

.. code-block:: c

   HIPFILE_API hipFileError_t hipFileReadAsync(hipFileHandle_t fh,
                                               void *buffer_base,
                                               size_t *size_p,
                                               hoff_t *file_offset_p,
                                               hoff_t *buffer_offset_p,
                                               ssize_t *bytes_read_p,
                                               hipStream_t stream);

:param fh: Registered hipFile file handle.
:param buffer_base: Base address of the GPU buffer.
:param size_p: Pointer to the number of bytes that should be read.
:param file_offset_p: Pointer to the offset into the file that should be
   read from.
:param buffer_offset_p: Pointer to the offset of the GPU buffer that the data
   should be written to.
:param bytes_read_p: Pointer populated with the number of bytes read after the
   operation completes on the stream.
:param stream: HIP stream on which to enqueue the read.
:returns: ``hipFileError_t`` with ``hipFileSuccess`` on success or an
   appropriate error code on failure.

.. note::

   The ``size_p``, ``file_offset_p``, and ``buffer_offset_p`` parameters are
   pointers, not values. The library reads the pointed-to values at
   submission time (when the operation is dequeued from the stream), not at
   the time you call ``hipFileReadAsync``. The memory backing these pointers
   must remain valid and unmodified until the stream operation has completed.
   Failing to keep the pointers live can result in undefined behavior.

``hipFileWriteAsync``
---------------------

Perform an asynchronous write from a GPU buffer to a file on the specified
stream.

.. code-block:: c

   HIPFILE_API hipFileError_t hipFileWriteAsync(hipFileHandle_t fh,
                                                void *buffer_base,
                                                size_t *size_p,
                                                hoff_t *file_offset_p,
                                                hoff_t *buffer_offset_p,
                                                ssize_t *bytes_written_p,
                                                hipStream_t stream);

:param fh: Registered hipFile file handle.
:param buffer_base: Base address of the GPU buffer.
:param size_p: Pointer to the number of bytes that should be written.
:param file_offset_p: Pointer to the offset into the file that should be
   written to.
:param buffer_offset_p: Pointer to the offset of the GPU buffer that the data
   should be read from.
:param bytes_written_p: Pointer populated with the number of bytes written
   after the operation completes on the stream.
:param stream: HIP stream on which to enqueue the write.
:returns: ``hipFileError_t`` with ``hipFileSuccess`` on success or an
   appropriate error code on failure.

.. note::

   The pointer-semantics note for ``hipFileReadAsync`` applies equally here:
   ``size_p``, ``file_offset_p``, and ``buffer_offset_p`` must outlive the
   async submission and remain valid until the stream operation completes.
