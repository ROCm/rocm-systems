======================
Batch IO API reference
======================

.. warning::

   Batch IO is not yet supported on AMD backends in the current release. Calling
   batch IO functions on an AMD backend returns error codes. On NVIDIA platforms,
   batch IO is dispatched through the cuFile backend.

This page documents the hipFile batch IO surface: the handle lifecycle functions
for creating and destroying batch contexts, the submission and status-polling
functions, and all associated types and enumerations.

For file handle and buffer registration (prerequisites for batch IO requests),
see :doc:`/reference/api-file-handle-and-buffer`.

*Declared in:* ``include/hipfile.h``

Data types
**********

``hipFileBatchHandle_t``
------------------------

Opaque batch operations handle.

.. code-block:: c

   typedef void *hipFileBatchHandle_t;

A ``hipFileBatchHandle_t`` is obtained from ``hipFileBatchIOSetUp`` and passed
to all other batch IO functions. Release it with ``hipFileBatchIODestroy`` when
it is no longer needed.

``hipFileOpcode_t``
-------------------

The direction of data movement in a batch IO request.

.. code-block:: c

   typedef enum hipFileOpcode {
       hipFileBatchRead  = 0,
       hipFileBatchWrite = 1,
   } hipFileOpcode_t;

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Value
     - Description
   * - ``hipFileBatchRead``
     - Read batch IO operation
   * - ``hipFileBatchWrite``
     - Write batch IO operation

``hipFileStatus_t``
-------------------

The status of a batch IO operation. Values are bit flags.

.. code-block:: c

   typedef enum hipFileStatus {
       hipFileWaiting  = 1 << 0,
       hipFilePending  = 1 << 1,
       hipFileInvalid  = 1 << 2,
       hipFileCanceled = 1 << 3,
       hipFileComplete = 1 << 4,
       hipFileTimeout  = 1 << 5,
       hipFileFailed   = 1 << 6,
   } hipFileStatus_t;

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Value
     - Description
   * - ``hipFileWaiting``
     - Batch IO operation pending acceptance
   * - ``hipFilePending``
     - Batch IO operation accepted and queued
   * - ``hipFileInvalid``
     - Batch IO operation was rejected for being invalid or could not be queued
   * - ``hipFileCanceled``
     - Batch IO operation was canceled
   * - ``hipFileComplete``
     - Batch IO operation completed
   * - ``hipFileTimeout``
     - Batch IO operation timed out
   * - ``hipFileFailed``
     - Batch IO operation failed

``hipFileIOParams_t``
---------------------

Input parameters for a batch IO request.

.. code-block:: c

   typedef struct hipFileIOParams {
       hipFileBatchMode_t mode;
       union {
           struct {
               void   *devPtr_base;
               int64_t file_offset;
               int64_t devPtr_offset;
               size_t  size;
           } batch;
       } u;
       hipFileHandle_t fh;
       hipFileOpcode_t opcode;
       void           *cookie;
   } hipFileIOParams_t;

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - Field
     - Description
   * - ``mode``
     - Mode of the batch IO request (see ``hipFileBatchMode_t``)
   * - ``u.batch.devPtr_base``
     - Base address of the GPU buffer where data should be read into or written from
   * - ``u.batch.file_offset``
     - Offset into the file that should be read from or written to
   * - ``u.batch.devPtr_offset``
     - Offset of the GPU buffer that should be read from or written to
   * - ``u.batch.size``
     - Number of bytes to read or write
   * - ``fh``
     - Registered hipFile handle for the target file
   * - ``opcode``
     - Direction data is moving for the batch request (see ``hipFileOpcode_t``)
   * - ``cookie``
     - Optionally used to track IO operations (for example, a self-reference pointer)

``hipFileIOEvents_t``
---------------------

Status of a completed (or in-progress) batch IO operation, returned by
``hipFileBatchIOGetStatus``.

.. code-block:: c

   typedef struct hipFileIOEvents {
       void           *cookie;
       hipFileStatus_t status;
       size_t          ret;
   } hipFileIOEvents_t;

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - Field
     - Description
   * - ``cookie``
     - Optionally used to track IO operations (for example, a pointer to the corresponding ``hipFileIOParams_t``)
   * - ``status``
     - Status of the batch IO operation (see ``hipFileStatus_t``)
   * - ``ret``
     - Number of bytes transferred, or a POSIX error code if negative

Functions
*********

``hipFileBatchIOSetUp``
-----------------------

Prepare the system to perform a batch IO operation.

.. code-block:: c

   HIPFILE_API hipFileError_t hipFileBatchIOSetUp(hipFileBatchHandle_t *batch_idp, unsigned max_nr)

:param batch_idp: Receives the opaque batch handle on success.
:param max_nr: Maximum number of requests that can be submitted to this batch handle.
:returns: ``hipFileError_t`` indicating the result of the operation.

``hipFileBatchIOSubmit``
------------------------

Enqueue a batch of IO requests for the GPU to complete asynchronously.

.. code-block:: c

   HIPFILE_API hipFileError_t hipFileBatchIOSubmit(hipFileBatchHandle_t batch_idp, unsigned nr,
                                                   hipFileIOParams_t *iocbp, unsigned flags)

:param batch_idp: Batch handle obtained from ``hipFileBatchIOSetUp``.
:param nr: Number of batch IO requests to submit.
:param iocbp: An array of ``nr`` batch IO requests to submit to the GPU. Data is read into or written from the buffer specified in each request.
:param flags: Control flags for the batch IO. Currently unused.
:returns: ``hipFileError_t`` indicating the result of the operation.

``hipFileBatchIOGetStatus``
---------------------------

Poll for the status of completed batch IO operations.

.. code-block:: c

   HIPFILE_API hipFileError_t hipFileBatchIOGetStatus(hipFileBatchHandle_t batch_idp, unsigned min_nr,
                                                      unsigned *nr, hipFileIOEvents_t *iocbp,
                                                      struct timespec *timeout)

:param batch_idp: Batch handle obtained from ``hipFileBatchIOSetUp``.
:param min_nr: Minimum number of batch operation statuses that should be returned. If ``timeout`` is exceeded, fewer statuses might be returned.
:param nr: On input, maximum number of batch operation statuses that can be returned. On output, modified to reflect the number of statuses returned in ``iocbp``.
:param iocbp: An array containing up to ``nr`` statuses from the overall batch operation.
:param timeout: Maximum amount of time this function should poll for status updates.
:returns: ``hipFileError_t`` indicating the result of the operation.

``hipFileBatchIOCancel``
------------------------

Cancel all pending batch IO operations.

.. code-block:: c

   HIPFILE_API hipFileError_t hipFileBatchIOCancel(hipFileBatchHandle_t batch_idp)

:param batch_idp: Batch handle obtained from ``hipFileBatchIOSetUp``.
:returns: ``hipFileError_t`` indicating the result of the operation.
