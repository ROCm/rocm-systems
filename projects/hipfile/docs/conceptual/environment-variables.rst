==============================
Environment variable reference
==============================

hipFile reads several environment variables at startup to configure IO backend
selection, statistics collection, and filesystem restrictions. These variables
let you tune hipFile behavior without recompiling your application or modifying
source code.

All variables are read from the process environment. When a variable is unset,
hipFile uses its documented default. Setting a variable to an unrecognized value
causes hipFile to treat it as unset.

Variable reference
******************

The following table summarizes every environment variable that hipFile
recognizes.

.. list-table::
   :header-rows: 1
   :widths: 30 12 12 46

   * - Variable
     - Type
     - Default
     - Description
   * - ``HIPFILE_ALLOW_COMPAT_MODE``
     - Boolean
     - ``true``
     - Allow IO operations to fall back to the POSIX IO path when the fastpath
       cannot service a request.
   * - ``HIPFILE_FORCE_COMPAT_MODE``
     - Boolean
     - ``false``
     - Force all IO operations to use the POSIX IO (fallback) path, disabling
       the fastpath entirely.
   * - ``HIPFILE_STATS_LEVEL``
     - Unsigned integer
     - ``1``
     - Control how much information is collected for the ``ais-stats``
       statistics tool.
   * - ``HIPFILE_UNSUPPORTED_FILE_SYSTEMS``
     - Boolean
     - ``false``
     - Allow the fastpath backend to operate on filesystems other than ext4
       (with ordered journaling) and xfs.

``HIPFILE_ALLOW_COMPAT_MODE``
-----------------------------

When the fastpath backend cannot complete an IO request — for example, because
the file was not opened with ``O_DIRECT``, offsets are misaligned, or the
kernel driver returns certain errors — hipFile can automatically retry the
request through the POSIX IO (fallback) path. This variable controls whether
that fallback is permitted.

* **``true``** (default): The fallback path is available. IO requests that
  fail on the fastpath are retried through POSIX ``pread`` or ``pwrite`` with
  ``hipMemcpy`` bounce buffering.
* **``false``**: The fallback path is disabled. IO requests that the fastpath
  cannot handle are rejected with an error.

Set this to ``false`` when you need to verify that every IO operation takes the
direct GPU DMA path and want failures to surface immediately rather than
silently falling back.

For a deeper explanation of how the two backends interact, see
:doc:`/conceptual/io-backends`.

``HIPFILE_FORCE_COMPAT_MODE``
-----------------------------

This variable overrides normal backend selection and routes all IO through the
POSIX fallback path regardless of whether the fastpath conditions are met.

* **``false``** (default): hipFile selects the backend normally. The fastpath
  is used when all preconditions (``O_DIRECT``, device memory, supported
  filesystem, proper alignment) are satisfied.
* **``true``**: The fastpath backend is disabled. Every ``hipFileRead`` and
  ``hipFileWrite`` call uses POSIX IO with CPU-side bounce buffering.

This is useful for isolating performance differences between the two paths
or for working around a system configuration that prevents the fastpath from
functioning.

.. note::

   ``HIPFILE_FORCE_COMPAT_MODE=true`` takes precedence over
   ``HIPFILE_ALLOW_COMPAT_MODE``. When the fastpath is forced off, the compat
   mode setting is irrelevant because the fallback path is the only path.

``HIPFILE_STATS_LEVEL``
-----------------------

Controls the verbosity of runtime statistics that hipFile exposes to the
``ais-stats`` tool. The statistics include bytes transferred, bandwidth,
latency, and error counts broken down by backend and IO-size histogram
buckets.

.. list-table::
   :header-rows: 1
   :widths: 10 90

   * - Value
     - Behavior
   * - ``0``
     - Statistics collection is disabled. No data is recorded.
   * - ``1``
     - Basic statistics are collected (the default).
   * - ``2``
     - Detailed statistics. Currently identical to level 1; reserved for
       future expansion.

To collect statistics from a running application, export the variable before
launch and use the ``ais-stats`` command-line tool:

.. code-block:: bash

   export HIPFILE_STATS_LEVEL=1
   ais-stats ./my_application --input data.bin

For step-by-step instructions on collecting and interpreting statistics, see
:doc:`/how-to/collect-io-statistics`.

``HIPFILE_UNSUPPORTED_FILE_SYSTEMS``
------------------------------------

The fastpath backend accepts IO targeting block devices or regular files on
ext4 (with ordered journaling mode) or xfs filesystems. Files residing on
other filesystems are rejected by the fastpath, which might cause the request
to fall back to the POSIX path (if ``HIPFILE_ALLOW_COMPAT_MODE`` is ``true``)
or to fail outright.

Setting this variable to ``true`` bypasses the filesystem check, allowing the
fastpath to attempt direct GPU DMA on filesystems that hipFile does not
officially validate.

* **``false``** (default): Only ext4 (ordered) and xfs are accepted on the
  fastpath.
* **``true``**: The filesystem type check is skipped.

.. warning::

   Using the fastpath on untested filesystems might lead to data corruption or
   IO errors. Set this variable only if you have confirmed that the target
   filesystem and kernel driver support the ``O_DIRECT`` semantics that hipFile
   relies on.

For more information about filesystem requirements and backend selection
criteria, see :doc:`/conceptual/io-backends`.

Boolean value format
********************

Boolean environment variables accept the string values ``true`` and ``false``
(case-sensitive match of the values the ``Environment::get<bool>`` template
resolves). If a variable is set to any other value, hipFile treats it as unset
and applies the default.
