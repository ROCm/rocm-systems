========================================
Collect IO statistics with ``ais-stats``
========================================

The ``ais-stats`` tool collects runtime hipFile IO statistics from an application. Use it for quick performance checks and to verify which IO backend (fastpath or fallback) your workload is using.

Prerequisites
*************

Before collecting statistics, configure the target application's environment so that hipFile records metrics at runtime.

Set the ``HIPFILE_STATS_LEVEL`` environment variable to control the level of detail:

.. list-table::
   :header-rows: 1
   :widths: 15 85

   * - Value
     - Description
   * - ``0``
     - Disabled — no statistics are recorded.
   * - ``1``
     - Basic statistics are collected (registrations, bytes transferred, bandwidth, latency, errors, and IO-size histograms).
   * - ``2``
     - Reserved for future detailed reporting. Currently behaves the same as ``1``.

The variable must be visible to the process that loads ``libhipfile``. If it is unset or set to ``0``, hipFile does not record statistics and ``ais-stats`` has nothing to report.

For background on ``HIPFILE_STATS_LEVEL`` and other environment variables, see :doc:`/conceptual/environment-variables`.

Run ``ais-stats``
*****************

``ais-stats`` supports two usage modes: **attach mode** and **launch mode**.

Attach to a running process
---------------------------

If your application is already running (and was started with ``HIPFILE_STATS_LEVEL`` set), attach to it by PID:

.. code-block:: shell

   ais-stats -p <PID>

By default, ``ais-stats`` waits until the target process exits and then prints the report. To print the report immediately without waiting, add the ``-i`` flag:

.. code-block:: shell

   ais-stats -p <PID> -i

Launch a new process
--------------------

To start an application and automatically collect statistics when it exits, pass the command line directly to ``ais-stats``:

.. code-block:: shell

   HIPFILE_STATS_LEVEL=1 ais-stats ./my_app --input data.bin

``ais-stats`` launches ``./my_app`` with the provided arguments, waits for it to exit, and then generates the report.

Statistics collected
********************

At ``HIPFILE_STATS_LEVEL=1``, hipFile records the following metrics:

- **File handle registrations** — number of calls to ``hipFileHandleRegister``.
- **Buffer registrations** — number of calls to ``hipFileBufRegister``.
- **Bytes read and written** — totals broken out by backend (fastpath and fallback).
- **Bandwidth** — average read and write bandwidth per backend (reported in GiB/s).
- **Latency** — average read and write latency per backend (reported in microseconds).
- **Error counts** — total IO errors per backend and operation type.
- **IO-size histograms** — the above metrics bucketed by IO request size (from 0–4 KiB up to 65536 KiB and above), reported per GPU.

For details on the fastpath and fallback backends, see :doc:`/conceptual/io-backends`.

Troubleshooting
***************

No report is produced
---------------------

1. Verify that ``HIPFILE_STATS_LEVEL`` is set to ``1`` or ``2`` in the environment of the target process.
2. Confirm that ``ais-stats`` is available in your ``PATH``.
3. Check that the target process actually performed hipFile IO (for example, calls to ``hipFileRead`` or ``hipFileWrite``). If no hipFile operations occurred, there are no statistics to report.

Attach fails with ``-p <PID>``
------------------------------

- Confirm the PID refers to a running process.
- Verify that the current user has permission to inspect the target process. On many systems, attaching to another user's process requires elevated privileges.

All values are zero
-------------------

- Confirm the workload exercised the backend you expected. For example, if you expected fastpath IO but the file was opened without ``O_DIRECT``, hipFile uses the fallback path instead. Verify that the corresponding column in the report contains non-zero values.
- Review the IO-size histogram to see whether data transferred through a different size bucket than anticipated.

Statistics collection requires a Linux kernel version 5.3 or later.
