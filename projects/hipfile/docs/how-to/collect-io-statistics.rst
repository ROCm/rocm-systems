*************************************
Collect I/O statistics with ais-stats
*************************************

hipFile includes a built-in statistics collection framework and a companion tool, ``ais-stats``, that connects to a running hipFile process to report I/O bandwidth, latency, and error histograms. 

:doc:`/conceptual/statistics-collection` describes how hipFile records I/O statistics inside the process. :doc:`/reference/ais-stats-tool` documents the ``ais-stats`` CLI and the fields in its report.

Prerequisites
*************

- A hipFile workload, such as ``aiscp`` or your own application using the hipFile C API or Python bindings
- The ``ais-stats`` tool, built as part of the hipFile project, typically under ``build/tools/ais-stats/`` when built from source
- Sufficient permissions to open a ``pidfd`` to the target process, typically as the same user or as root
- Linux kernel 5.3 or later with ``pidfd_open`` support for attaching to a running process

Enable statistics collection
****************************

This is step 1 of the workflow. hipFile controls statistics collection through the ``HIPFILE_STATS_LEVEL`` environment variable. Set this variable before launching the hipFile workload:

- ``0``: Histogram recording is disabled. Shared-memory infrastructure may still initialize.
- ``1``, default when unset: Basic statistics are collected, including per-GPU and per-backend bandwidth, latency, and error histograms.
- ``2`` or higher: Reserved for future detail levels. Current releases collect the same histograms as level ``1``.

.. code:: shell

For background on ``HIPFILE_STATS_LEVEL`` and other environment variables, see :doc:`/conceptual/environment-variables`.

.. note::

    The ``HIPFILE_STATS_LEVEL`` environment variable must be set in the environment of the hipFile process you want to monitor. Setting it after the process has started has no effect.

Run a hipFile workload
**********************

This is step 2 of the workflow. Launch your hipFile application with statistics enabled. For example, using the ``aiscp`` example program:

.. code:: shell

   HIPFILE_STATS_LEVEL=1 ./aiscp /path/to/source /path/to/dest &

Note the process ID (PID) of the running workload. You can find it with:

.. code:: shell

   echo $!

Or use standard tools such as ``ps`` or ``pgrep``.

Attach ais-stats to the process
*******************************

This is step 3 of the workflow. With the hipFile process running and its PID known, attach ``ais-stats`` with the ``-p`` flag:

.. code:: shell

   ais-stats -p <PID>

Replace ``<PID>`` with the actual process ID of the hipFile workload. To print a snapshot while the process is still running, add ``-i``:

.. code:: shell

   ais-stats -p <PID> -i

The tool performs the following actions:

1. Opens a process file descriptor (``pidfd``) for the target process.
2. Connects to the hipFile statistics server running inside the target process.
3. Blocks until the target process exits, unless you pass ``-i`` for an immediate snapshot.
4. Generates a formatted report and writes it to standard output.

Interpreting the output
***********************

The ``ais-stats`` report contains per-GPU, per-backend (fastpath and fallback) histogram data for the following metrics:

I/O size histogram
   Shows the distribution of I/O request sizes in bytes. Each bucket covers a power-of-two range starting at 4 KiB (2\ :sup:`12` bytes). There are up to 16 buckets, with the last bucket capturing all sizes above its lower bound.

I/O bandwidth histogram
   Shows derived bandwidth (GiB/s) per size bucket, computed from bytes transferred and elapsed time.

I/O latency histogram
   Shows the distribution of I/O operation latency in microseconds, using the same bucket structure as size.

I/O errors histogram
   Shows the count of failed I/O operations per size bucket.

Each metric is reported separately for read and write operations, and separately for the fastpath and fallback backends. Only GPUs that performed I/O operations appear in the report.

Histogram bucket ranges
^^^^^^^^^^^^^^^^^^^^^^^

The histogram uses logarithmic bucket boundaries:

- Bucket 0: 0 to 4 KiB
- Bucket 1: 4 KiB to 8 KiB
- Bucket 2: 8 KiB to 16 KiB
- Each subsequent bucket doubles the range
- Bucket 15, the last bucket: 64 MiB and above

Common variations
*****************

``ais-stats`` supports two usage modes: **attach mode** and **launch mode**.

By default, ``ais-stats -p`` waits for the target process to exit before generating the final report. Pass ``-i`` to generate a report immediately without waiting.

Using higher statistics levels
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Level ``2`` and above are reserved for future releases. Setting a higher value does not change histogram collection in current builds:

.. code:: shell

   ais-stats -p <PID>

See :doc:`/conceptual/statistics-collection` for the supported levels.

Troubleshooting
***************

``ais-stats`` cannot find the target process
   Make sure the PID is correct and the process is still running. The ``ais-stats`` tool returns an error if the target process has already exited or is not accessible.

No statistics in the report
   Confirm that ``HIPFILE_STATS_LEVEL`` was set to ``0`` explicitly if you intended to disable collection. When the variable is unset, the default is ``1`` and statistics are collected.

Attach fails with ``-p <PID>``
------------------------------

- Confirm the PID refers to a running process.
- Verify that the current user has permission to inspect the target process. On many systems, attaching to another user's process requires elevated privileges.

All values are zero
-------------------

- Confirm the workload exercised the backend you expected. For example, if you expected fastpath IO but the file was opened without ``O_DIRECT``, hipFile uses the fallback path instead. Verify that the corresponding column in the report contains non-zero values.
- Review the IO-size histogram to see whether data transferred through a different size bucket than anticipated.

Statistics collection requires a Linux kernel version 5.3 or later.
