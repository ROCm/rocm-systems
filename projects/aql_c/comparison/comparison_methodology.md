# AQL Packet Comparison Methodology

## Overview

This document outlines the methodology for comparing AQL packets generated by two different implementations:
1. **aql_c**: The new C-based kernel-compatible implementation
2. **aqlprofile_v2**: The existing AQLProfile v2 implementation

The goal is to ensure that aql_c generates functionally equivalent packets to aqlprofile_v2 for the same counter configurations.

## Comparison Strategy

### 1. Test Case Design

#### Common Test Scenarios
- **Single Counter**: Test with one counter from different blocks (CPC, GRBM, SQ, etc.)
- **Multiple Counters**: Test with multiple counters from the same block
- **Cross-Block Counters**: Test with counters from different blocks
- **Architecture Variants**: Test across different GPU architectures (GFX9, GFX10, GFX11, GFX12)
- **Instance Variations**: Test different block instances where applicable

#### Counter Selection Matrix
```
Architecture | Block Types | Instance Count | Event IDs
-------------|-------------|----------------|----------
GFX9         | CPC, GRBM, SQ, TCA, TCC | 0-3 | 100-200
GFX10        | CPC, GRBM, SQ, GL1A, GL1C | 0-3 | 100-200
GFX11        | CPC, GRBM, SQ, GL2A, GL2C | 0-3 | 100-200
GFX12        | CPC, GRBM, SQ, CHA, CHC | 0-3 | 100-200
```

### 2. Packet Extraction and Analysis

#### Packet Components to Compare
1. **Start Packet (PM4 IB)**
   - Header fields
   - PM4 command buffer content
   - Register programming sequences
   - Memory allocation requirements

2. **Stop Packet (PM4 IB)**
   - Counter disable commands
   - State restoration commands

3. **Read Packet (PM4 IB)**
   - Memory copy operations
   - Counter result retrieval
   - Buffer management

#### Comparison Granularity
- **Byte-level**: Exact binary comparison of packet contents
- **Semantic-level**: Functional equivalence of PM4 commands
- **Register-level**: Individual register programming operations
- **Buffer-level**: Memory layout and addressing

## Implementation Programs

### 1. AQL_C Dumper Program

**File**: `aql_c_dumper.c`

**Purpose**: Create AQL packets using aql_c interface and dump them in standardized format

**Key Features**:
- Command-line interface for specifying counters
- Support for multiple architectures
- Binary and JSON output formats
- Detailed PM4 command decoding
- Memory buffer content extraction

**Usage**:
```bash
./aql_c_dumper --arch gfx942 --counter CPC:0:123 --counter GRBM:0:456 --output test1.json
./aql_c_dumper --arch gfx942 --counter SQ:0:789 --format binary --output test2.bin
```

### 2. AQLProfile v2 Dumper Program

**File**: `aqlprofile_v2_dumper.c`

**Purpose**: Create AQL packets using aqlprofile v2 interface and dump them in the same format

**Key Features**:
- Identical command-line interface to aql_c_dumper
- Same output formats for direct comparison
- Error handling and validation
- Memory allocation callback implementation

**Usage**:
```bash
./aqlprofile_v2_dumper --arch gfx942 --counter CPC:0:123 --counter GRBM:0:456 --output test1_ref.json
```

### 3. Packet Comparison Tool

**File**: `packet_compare.py`

**Purpose**: Compare outputs from both dumpers and identify differences

**Key Features**:
- Binary diff with offset reporting
- Semantic diff of PM4 commands
- Register programming analysis
- Visual diff output with highlighting
- Batch comparison for test suites

**Usage**:
```bash
./packet_compare.py test1.json test1_ref.json --detailed
./packet_compare.py --batch test_results/ reference_results/
```

## Detailed Comparison Criteria

### 1. Packet Header Analysis
- AQL packet type and format fields
- Dependency handling
- Completion signal setup

### 2. PM4 Command Sequence Analysis
- Command ordering and grouping
- Register address calculations
- Value programming patterns
- GRBM index management

### 3. Memory Layout Analysis
- Buffer allocation sizes
- Memory alignment requirements
- Address space usage (CONFIG vs UCONFIG)
- DMA coherency settings

### 4. Architecture-Specific Validation
- GFX9: UCONFIG register usage, PRED_EXEC packets
- RDNA: GL1/GL2 programming, WGP addressing
- GFX12: New block support, extended features

## Test Case Execution Plan

### Phase 1: Basic Validation
1. Single counter tests for each major block type
2. Architecture coverage (GFX9, GFX10, GFX11, GFX12)
3. Binary packet comparison

### Phase 2: Functional Validation
1. Multi-counter configurations
2. Cross-block counter combinations
3. Semantic PM4 command analysis

### Phase 3: Stress Testing
1. Maximum counter configurations
2. Edge case scenarios (unusual block instances)
3. Error condition handling

### Phase 4: Performance Analysis
1. Packet generation timing
2. Memory usage comparison
3. Resource allocation patterns

## Automated Test Framework

### Test Runner Script

**File**: `run_comparison_tests.sh`

**Features**:
- Automated test case generation
- Parallel execution of both dumpers
- Result collection and analysis
- Report generation with diff summaries

**Usage**:
```bash
./run_comparison_tests.sh --arch gfx942 --test-suite basic
./run_comparison_tests.sh --arch all --test-suite full --parallel 8
```

### Expected Output Analysis

#### Perfect Match
- Binary identical packets
- Identical PM4 command sequences
- Same memory allocation patterns

#### Acceptable Differences
- Different memory addresses (but same relative layout)
- Different buffer ordering (if functionally equivalent)
- Architecture-specific optimizations

#### Problematic Differences
- Different register programming sequences
- Missing or extra PM4 commands
- Incorrect counter block assignments
- Wrong memory allocation sizes

## Integration with Development Workflow

### Continuous Integration
1. **Commit Hooks**: Run basic comparison tests on aql_c changes
2. **Nightly Builds**: Execute full test suite across all architectures
3. **Release Validation**: Comprehensive comparison before version releases

### Development Guidelines
1. **New Features**: Add corresponding test cases to comparison framework
2. **Bug Fixes**: Verify that fixes maintain compatibility with aqlprofile_v2
3. **Architecture Support**: Extend test coverage for new GPU architectures

This methodology ensures thorough validation of aql_c's compatibility with aqlprofile_v2 while providing clear frameworks for identifying and resolving any discrepancies.
