* Fixed an extra `hipEventRecord` of the parent done event after every hierarchical `ncclReduceScatter`. The shuffle runs first and cannot carry the stop event, and the intra-node and inter-node collectives fuse their own communicators' done events, so the addon epilogue recorded the parent event on the user stream after the call. The last inter-node kernel now takes that event as its stop event, and the epilogue does not record it again. On 8 nodes of MI350X (64 GPUs) with hierarchical ReduceScatter enabled, float ReduceScatter from 1 KB to 1 MB was about 10 to 13% slower than before the addon launch ordering; with this change it stays within 2% of that baseline.
