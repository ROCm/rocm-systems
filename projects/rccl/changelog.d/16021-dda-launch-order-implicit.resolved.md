* Fixed `NCCL_LAUNCH_ORDER_IMPLICIT=1` (or `launchOrderImplicit=1`) silently disabling the DDA AllReduce, AllGather, ReduceScatter, Broadcast and AlltoAll paths. Addon collective launches now join the per-device implicit launch order like native kernel launches, so DDA stays eligible. Before the fix, setting the variable moved small collectives onto the ring kernels, which changed bf16 reduction order and results (for example, vLLM data-parallel + expert-parallel serving gave different greedy outputs per replica). With the variable on, every addon launch (DDA, CE, hierarchical and GIN-SDMA) is serially ordered: CE collectives perform at parity with the previous behavior, DDA paths are faster than the ring kernels they replaced, and GIN-SDMA has not yet been measured.
