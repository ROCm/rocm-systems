* NaN-flag protocol, selected with `NCCL_PROTO=NaN` (in any case; a list such as `LL,NaN` does not select it). It runs float (f16, bf16, f32, f64) `ncclAllReduce` on ring and tree, ring `ncclAllGather` and `ncclReduceScatter`, and the intra-node send/recv halves of `ncclAlltoAll`, single-node Direct AllGather and Direct ReduceScatter; other collectives and datatypes keep the default protocols. A receiver reads an all-ones dword as not yet written, so the sender lowers every all-ones dword of the data (for f64, every all-ones high dword) to `0xFFFFFFFE`, which is still a NaN, on every rank. `RCCL_NAN_PROTO_AUTO=1` uses the protocol only in the message-size windows where it measured faster than the default selection, on gfx950 with 8 GPUs per node, and is off when `NCCL_PROTO` is set and for a call whose `algSelection` names no `NAN` row (`TREE_NAN`, `RING_NAN`). `NCCL_NAN_BUFFSIZE` sets the NaN FIFO size per connection: 4 MiB where `NCCL_PROTO=NaN` or `RCCL_NAN_PROTO_AUTO` applies, else `0`, rounded down to whole 4 KiB grains per FIFO step (2 KiB on wave32), and a communicator with no NaN FIFO, or one smaller than a grain per step, never selects the protocol. Builds with `install.sh --enable-tdm-nan` (`-DENABLE_TDM_NAN=ON`) add a gfx1250 tensor data mover path with an 8 MiB NaN FIFO, on by default (`RCCL_TDM_NAN_ENABLE`, default `1`) for primitive operations from `RCCL_TDM_NAN_MIN_BYTES` (default `65536`).
