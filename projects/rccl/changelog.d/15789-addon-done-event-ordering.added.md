* `RCCL_ADDON_DONE_EVENT_ORDERING` to disable done event ordering for addon collectives that launch on the user's stream through `rcclAddonLaunch` (DDA, hierarchical, GIN SDMA, and Copy Engine 2-shot AllReduce and ReduceScatter). It is on by default. With `RCCL_ADDON_DONE_EVENT_ORDERING=0`, those launches neither wait on nor record the communicator's done event, and the application must order collectives issued on different streams itself. Collectives on the native enqueue path, including Copy Engine collectives launched by `ncclLaunchCeColl`, are unaffected and still wait on and record the done event. With `0`, destroy and abort use a device-wide sync, because the done event no longer covers in-flight addon work on the user's stream.
