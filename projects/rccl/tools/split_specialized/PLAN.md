# Split Specialized Kernel Pipeline

## Overview

Replace the custom device_linker ELF merger with a bitcode-to-assembly pipeline that compiles specialized kernels with -fgpu-rdc, strips kernel entries from assembly, and uses the standard LLVM linker (lld) to combine device objects — eliminating the custom tool while avoiding both the LDS warning and IFC code-generation constraints.

## Approach

Each specialized kernel `.cpp` defines both `ncclDevFunc_*` (device function) and `ncclDevKernel_*` (global kernel). The kernel wrapping the function means the compiler sees LDS used in a kernel context (no warning) and generates unconstrained code. After compilation to assembly, we strip the kernel metadata, keeping only the callable device function. The standard linker then combines everything.

## Pipeline (per specialized kernel)

```
specialized.cpp
    |  -fgpu-rdc --offload-device-only -emit-llvm
    v
  .bc
    |  -x ir -target amdgcn -S
    v
  .s -----> grep amdgpu.max_num ----> .meta
    |
    |  strip_kernel.py
    v
stripped.s
    |  -x assembler -c
    v
  .o
```

## Pipeline (dispatcher = common.cu)

```
common.cu
    |  bc step
    v
  .bc
    |  asm step
    v
  .s
    |  patch_kernel_metadata.cmake (using .meta files)
    v
patched.s
    |  -x assembler -c
    v
  .o
```

## Pipeline (link + embed)

```
all device .o files
    |  lld -r
    v
combined.o
    |  lld -shared
    v
combined.so
    |  clang-offload-bundler
    v
  .hipfb
    |  host compile -fcuda-include-gpubinary
    v
fat.o  ----> link into librccl.so
```

## What Gets Stripped from Each Specialized Kernel `.s`

Each specialized kernel `.s` contains:

- **Keep**: `ncclDevFunc_*` function body (code in `.text`, ends with `s_setpc_b64`)
- **Keep**: `.set amdgpu.max_num_*` directives (also extracted to `.meta` sidecar)
- **Strip**: `ncclDevKernel_*` kernel body (code in `.text`, ends with `s_endpgm`)
- **Strip**: `.amdhsa_kernel ... .end_amdhsa_kernel` block (generates kernel descriptor)
- **Strip**: Kernel's YAML entry in `.amdgpu_metadata` section
- **Strip**: `.globl` / `.type` / `.size` directives for the kernel symbol

The stripping script asserts exactly one `ncclDevKernel_*` kernel per `.s` file.
Multiple kernels is a fatal error (generation or compilation bug).

## Function Table Population

The standard `device_table.h` (generated by `generate.py`) defines
`ncclDevFuncTable_{1,2,4}` with function pointer references to `ncclDevFunc_*`.

In `common.h`:

```cpp
#if !defined(NCCL_SPECIALIZED_KERNEL) && !defined(DEVICE_LINKER)
#include "device_table.h"
#endif
```

- Specialized kernels define `NCCL_SPECIALIZED_KERNEL`, so they skip `device_table.h`
  (correct; they only define their own `ncclDevFunc_*`).
- The dispatcher (common.cu) does NOT define either, so it includes `device_table.h`
  and gets the table definitions with function pointer references.
- With `-fgpu-rdc`, these references become relocations resolved by `lld` at link time.

Code changes needed: remove the `DEVICE_LINKER`-specific empty table definitions in
`common.cu` and the extern declarations in `common.h`, and instead use the
`USE_INDIRECT_FUNCTION_CALL` + `device_table.h` path.

## Compiler Flags Summary

| Step                 | Flags                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------- |
| Source to bitcode    | `-x hip -std=c++17 -fgpu-rdc --offload-device-only --offload-arch=gfxXXX -emit-llvm -c -O3` |
| Bitcode to asm       | `-x ir -target amdgcn-amd-amdhsa -mcpu=gfxXXX -O3 -S`                                       |
| Asm to device obj    | `-x assembler -target amdgcn-amd-amdhsa -mcpu=gfxXXX -c`                                     |
| Device link (reloc)  | `lld -r -o combined.o *.o`                                                                   |
| Device link (shared) | `lld -shared -o combined.so combined.o`                                                      |
| Bundle               | `clang-offload-bundler --type=bc --targets=host-...,hipv4-amdgcn-...`                        |
| Host stub            | `-x hip --offload-host-only --offload-arch=gfxXXX -Xclang -fcuda-include-gpubinary -Xclang combined.hipfb` |

## Metadata Sidecar Sufficiency

The sidecar (`.meta`) captures `amdgpu.max_num_{vgpr,agpr,sgpr}` from each specialized
kernel's assembly. This is sufficient for both the binary KD and the .note YAML:

**Binary KD** — the assembler auto-computes all fields from `.amdhsa_kernel` directives:

- **Registers**: RSRC1 (VGPR/SGPR granulated) and accum_offset are expressions
  referencing `amdgpu.max_num_*`. Patching the `.set` values cascades automatically.
- **LDS** (`.amdhsa_group_segment_fixed_size`): determined solely by
  `sizeof(ncclShmemData)` defined in `common.h`. Every TU includes the same `common.h`
  with an identical `__shared__ ncclShmemData ncclShmem` declaration. Dynamic LDS (if
  any) is declared as `extern __shared__ int foo[]` (zero-size, does not contribute to
  `group_segment_fixed_size`). LDS is therefore structurally uniform across all TUs — no
  patching needed. A mismatch indicates compile-definition drift (e.g., inconsistent
  `ENABLE_FAULT_INJECTION`).
- **Scratch** (`.amdhsa_private_segment_fixed_size`): kernel sets to 0. Callee stack
  usage handled by `uses_dynamic_stack: true` (HSA runtime allocates default ~8KB
  budget). Standard IFC behavior.

**.note YAML** — `patch_kernel_metadata.cmake` Step 3 patches `.vgpr_count`,
`.agpr_count`, `.sgpr_count` literals directly. LDS and scratch fields are correct as
emitted (same reasoning as KD).

**Safety checks the PoC must perform:**

1. Each specialized kernel `.s` has exactly one `.group_segment_fixed_size` value in the
   YAML; assert all are equal to the dispatcher's. A mismatch indicates compile-definition
   drift (fatal).
2. The dispatcher's assembly contains `.uses_dynamic_stack: true`. If absent, the runtime
   won't allocate callee scratch (fatal).

## Open Questions / Risks

1. **Symbol naming match**: Need to verify `generate_specialized.py` and `device_table.h`
   use identical `ncclDevFunc_*` symbol names. They appear to match
   (`ncclDevFunc_AllReduce_RING_SIMPLE_Sum_f32_0_0_2`), but should be verified in the PoC.
2. **No `-mllvm -amdgpu-allow-lds-in-non-entry-functions` needed**: Since the kernel is
   present during compilation, the LDS warning should not trigger. This is the core
   hypothesis to validate in the PoC.
