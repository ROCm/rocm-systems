## Root Cause Analysis

Detailed comparison between IFC (production) and device linker builds revealed key differences:

1. **Missing `__clang_gpu_used_external` symbol** - IFC has this 96-byte symbol in `.data` with 12 relocations pointing to oneRankReduce kernel entries. Device linker build is missing it entirely.

2. **Missing oneRankReduce kernels** - IFC has 12 oneRankReduce helper kernels in the dispatcher. Device linker used a stub instead.

3. **Function table linkage** - IFC uses `_ZL` (internal linkage), device linker uses external.

See `IFC_VS_DEVICE_LINKER_COMPARISON.md` for full comparison.

## Current Fix Being Implemented

### Phase 1: Add oneRankReduce kernels (COMPLETED)
Compile `onerank.cu` together with `common.cu` as a single compilation unit.

**Result:** 
- ✅ Dispatcher now has 15 kernels (3 Generic + 12 oneRankReduce)
- ✅ .note has 15 kernel metadata entries
- ❌ `__clang_gpu_used_external` NOT generated

**Finding:** `__clang_gpu_used_external` is generated by **lld during RDC device linking**, not by the compiler. IFC uses `-fgpu-rdc`, our build uses `-fno-gpu-rdc`.

### Phase 2: Manually create `__clang_gpu_used_external` (COMPLETED)
Since the symbol isn't auto-generated in non-RDC mode (only generated by lld in RDC linking), the device linker creates it manually.

**Implementation in device_linker.cpp:**
1. ✅ Collect oneRankReduce FUNC symbols from dispatcher by pattern matching
2. ✅ Store their text offsets in `onerank_text_offsets_` vector
3. ✅ `.data` section sized to 0x60 (96 bytes) for the symbol
4. ✅ Add 12 R_AMDGPU_RELATIVE64 relocations in `buildRelocations()`
5. ✅ Add `__clang_gpu_used_external` symbol to `.symtab` as LOCAL HIDDEN

**Verification (merged ELF):**
- `__clang_gpu_used_external` symbol at 0x1cb000, size 96 bytes
- 12 relocations pointing to oneRankReduce addresses (0x1cb000-0x1cb058)
- Total 871 relocations (859 function table + 12 oneRankReduce)
