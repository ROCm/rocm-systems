# Physical gfx950 campaign

This document preserves the September 17–18, 2026 thirteen-workload MI350X
campaign reported in [STATUS_GFX950.md](STATUS_GFX950.md). It has not been rerun
for the current branch. Commands, machine-local paths, progress notes, and
preset names below describe that campaign; consult artifact provenance before
comparing them with today's controls. The dated progress notes are retained to
explain the final results.

Columns follow this order: Uninstrumented, Default Mode, Default Mode
(`RJ_CONSAN_PRESET=high`), and SuperCollider. Each has Startup and Run values.
The two Default Mode variants explicitly use the default and high presets;
the high preset is not a separate sanitizer mode.

## Measurement and acceptance

The contract in [BENCHMARK.md](BENCHMARK.md) is unchanged: native profiler
discovery, an exact-name kernel allowlist, two native baseline processes,
correctness-checked instrumented variants, and a final native drift check.
Each process performs two identical synchronized operations; the first
includes selected host analysis, while the second measures sustainable device
instrumentation without repeating that analysis.

Numerical correctness and complete static instrumentation gate admission.
Dynamic race reports and bounded evidence-retention limitations remain in
artifacts; accepted performance cells do not establish exhaustive race coverage.
Inapplicable cells must be labeled as such, with no overhead claim.

The initial run exposed a parser conflict with ConSan's human-facing coverage
hint. Commit `2be652b683` excludes that exact prose prefix from structured
coverage parsing, preserving fail-closed checks for malformed or missing audit
records. Coverage and benchmark regression suites passed; the affected cells
were invalidated and rerun.

The hipBLASLt client then exposed a missing timing summary in the process-exit
fallback (the summary previously lived only in `OnUnload`). Commit
`b929ec3a63` moves it into shared, once-only finalization. All 200 hook host
tests passed in GCC and UBSan, together with 100 repetitions of each of four
lifecycle/timing tests in both builds. The hook fingerprint changed, so prior
measurements are invalidated rather than silently reused.

### TokenSpeed BF16 MoE admission diagnosis

The original failure reproduced: `applicable=false`, `static_complete=false`,
and zero applicable code objects. However, all four code-object inventories
completed successfully with zero sites, and all four exact-name allowlisted
kernels loaded and dispatched. The numerical CPU oracle passed.

At the unchanged eight-token shape, TokenSpeed selects
`_stage1_warp_gemv_gluon` and `_stage2_warp_gemv_gluon`. Their generated gfx950
assembly has zero group-segment allocation and no LDS accesses or barriers;
the reductions use wave-local registers. The other selected kernels perform
buffer copying and BF16-to-FP32 conversion. This workload is inapplicable to
LDS race instrumentation, rather than evidence of missed ConSan patches.
Native profiling also reports `LDS_Block_Size=0` for every dispatch.

The runner now distinguishes this proven zero-site case from a failed static
audit. It requires a complete zero-site inventory and dispatch proof for every
allowlist entry; incomplete analyses, expert limits, missing records, and
undispatched entries still fail. Inapplicable results are not accepted
performance measurements and carry no sanitizer overhead claims. Generated
assembly, code objects, hashes, and the initial audit classification are saved
in the preparation directory's `moe-zero-site-evidence/` subdirectory. All three
modes were run independently and confirmed the same inapplicability, with
passing numerical oracles and complete dispatch/inventory evidence.

### Completion results and timing limits

All selected rows completed profiler discovery, two native references, all
three modes, and final native validation. The physical GPU lock serialized
all runs. Final native Run drift was −1.02% for synthetic decode, +9.46% for
synthetic MoE prefill, and −0.72% for TokenSpeed MoE.

Synthetic MoE's native Run samples were 3.554 and 2.953 seconds; its final
native Run was 3.561 seconds. The final sample is close to the slower original
sample, but this spread limits interpretation of small overhead ratios.
Default Mode's 3.569 seconds and SuperCollider's 2.948 seconds do not establish
a meaningful difference from that native variation. In particular, do not
interpret SuperCollider's 0.906× ratio as a speedup. High mode's 43.2-second
Run (13.3×) is a much larger measured cost. Synthetic decode high also measured
a large Run cost: 17.9 seconds (5,330×). These measurements are retained without
replacing denominators or changing workloads to improve the reported ratios.

The new native Startup values and TokenSpeed MoE host latencies differ from the
historical campaign. The software stack and compiler provenance are explicit;
these changes must not be attributed to the benchmark classification fix.
That fix executes after a timed process exits. The ConSan hook remained
byte-identical throughout this completion run, and no instrumentation/runtime
source file changed.

Every applicable mode passed the CPU numerical oracle and full static site
audit. Default/high patched 1,254 sites each for decode and 2,354 each for
synthetic MoE; SuperCollider patched 986 and 2,007 respectively. The three
TokenSpeed MoE modes remain explicitly inapplicable, with no sanitizer timing
or ratio in their summaries. These are performance admission results, not
exhaustive race-freedom qualifications.

The selected-row executions took about 20.85 minutes (decode), 39.62 minutes
(synthetic MoE), and 6.08 minutes (TokenSpeed MoE), excluding preparation and
the archived initial failure reproduction. The 30-minute whole-suite aspiration
was not met. No workload was trimmed to meet it.

Regression validation passed 27 benchmark tests and 29 coverage-parser tests.
The preparation directory contains their logs, `live-runtime-libraries.json`,
and `audit-completion.py` / `completion-audit.json`. The final audit verifies
21 checkpoints, matches their numerical payloads and coverage against logs,
recomputes summaries and table values, checks gfx950/TheRock identity and the
16 GiB workload envelope, and confirms the unchanged hook hash and ten preserved
historical rows. Cell transitions and the classification fix were committed
incrementally. No benchmark process remains queued.
