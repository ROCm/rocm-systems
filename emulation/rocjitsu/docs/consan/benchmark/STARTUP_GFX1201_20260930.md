The source explains both broad analysis and duplicated work:

- `consan_cfg.h::build_cfg_inputs_for_selection` deliberately keeps whole-object
  CFG inputs when non-kernel functions exist, to preserve shared-helper ownership.
- `relay_flat_pointer_provenance_across_calls` builds another whole-object CFG
  when functions exist, and can re-decode kernel bodies during propagation.
- `annotate_execution_owners` and `ResourcePlanningState` derive scopes for all
  kernel owners; resource planning also computes liveness and register summaries.
- `prepare_automatic_transform` first creates an inventory. When no runtime
  evidence binding is needed, it called `transform`, whose staged path created
  another inventory and then performed complete lowering, creating a third
  inventory and resource-planning state even for an empty observation plan.

## Implemented first fix

Automatic preparation now returns its already-complete no-op inventory when
Default mode has a valid empty probe plan, complete evidence requirements with
no binding needed, and an unchanged, well-formed result. Injected executors,
debug overrides, mutation requests, invalid or unsupported inventory results,
incomplete evidence requirements, and nonempty probe plans retain their existing
paths. Initial semantic analysis still runs; this
is not an early assumption that a selected kernel has no relevant accesses.

This removes the redundant second and third inventories and no-op resource
planning. It is architecture-independent pipeline code. Regression coverage
checks no-op plans on gfx942, gfx950, gfx1100, gfx1201, and gfx1250, plus a real
LDS access excluded by an exact production allowlist, against the complete
transform's observation and evidence products. Physical speedups were measured
only on gfx1201; no physical gfx950 speedup is claimed.

## Next optimization targets

1. Keep a reusable decoded CFG and immutable instruction facts through inventory,
   binding, and resource planning instead of reconstructing equivalent graphs.
2. Bound helper analysis by selected roots and their call closure, while retaining
   all owners of any shared physical site that may be modified. Simply ignoring
   unselected owners can make register allocation or shared-helper patching unsafe.
3. Compute register-reference summaries once per immutable basic block, and
   aggregate them per owner. Context-sensitive liveness and return edges still
   need their existing correctness constraints.

The remaining 22–25 seconds in preparation are real overhead. The first fix
reduces duplication but does not solve whole-library analysis or remove the
need to profile gfx950 separately on hardware.

### Assertion-enabled indirect discovery

The no-indirect-consumer fast path still executed the complete auxiliary CFG
and dataflow analysis under `#ifndef NDEBUG`, solely to assert that it found no
fixups. This build uses `-UNDEBUG`, so that validation defeated the fast path.
`31a9d39a897` removes the shadow analysis without disabling assertions elsewhere.
Builds that already define `NDEBUG` do not gain from this change.

The deterministic regression test uses an instruction counting CFG branch
queries: no indirect consumer must mean zero auxiliary graph queries. It failed
before the fix on all five tested architectures and passes afterward. Existing
setpc/swappc recovery tests continue to verify consumer admission. The focused
CFG, indirect-discovery, and ownership suites passed all 156 tests.

### Repeated whole-library scans for kernel scopes

After traversing one kernel's reachable blocks, scope construction scanned every
block in the code object to recover their ordering. Repeating this for hundreds
of owners made a small local scope pay for the whole library. `a4d4d14b7af`
builds a block-position index once per immutable CFG and orders only each
reachable subset. All owners are still analyzed. Call/return traversal, ownership
proofs, and liveness edge construction retain their existing semantics.

The new regression covers 512 independent kernels, additional owned entries,
null vector slots, and deliberately reversed storage order. Existing shared-helper
and context-specific return-edge tests exercise the same implementation. The
focused run passed 1,165 tests, with two opt-in benchmark skips.

A fresh profile after this change (`dense-scope.perf.data`, main thread 1056503)
shows scope construction below the report's 5% cutoff, while cross-call pointer
relay remains about 16% of main-thread inclusive samples. CFG construction is
still about 31%. These overlapping relative shares are not phase durations.

### Invariant kernel decoding inside pointer relay

Pointer-provenance relay runs six helper-propagation passes. Each pass also
re-decoded every kernel from an empty entry tracker, generating the same root
call-site facts each time. `a78afb8d7f6` computes those kernel facts and warnings
once, then copies them into each pass. Helper entry states, six-pass limits,
conservative merges, failure rollback, and final diagnostics are unchanged.

The added regression calls a shared helper twice with either agreeing shared
pointers or conflicting shared/private pointers, verifying that cached root
facts preserve both call sites and their conservative merge. The focused run
passed 1,166 tests, with two opt-in benchmark skips.

Both workloads retain complete 996/996 and 867/867 selected-site coverage,
respectively, across five applicable objects, and pass their numerical oracles.

This shares decoded blocks, indirect-discovery results, and CFG edges between
relay and semantic synchronization/ownership analysis. It does not drop owners,
change entry policies, reduce decoding ranges, or reuse per-kernel liveness.

longer within an inventory call; only one cached graph is retained.

## Distributed cost: sparse and dense register-set iteration

This round examines a shared inlined helper rather than one ConSan pass.
`RegisterSet::for_each_ordinary` previously tested each possible register index:
106 SGPRs, 1,024 VGPRs, and 1,024 accumulator registers, even for tiny sets.
The maximum capacity supports all architectures, so gfx1201 also paid for high
VGPR banks it does not use. Callers include wait checking, indirect analysis,
liveness-related utilities, and resource planning. Source-line aggregation of
`dense-uniform-scope.perf.data` highlights multiple iterator lines; their cost
is distributed among template instantiations and inlined callers.

Commit `fb20cbaa50e` stores each ordinary class in an array of standard 64-bit bitsets.
Empty words are skipped, partial words use set-bit scans, and full words use a
simple index loop. This avoids library-private bitset layouts and compiler
extensions, preserves the public API, and adds no dynamic allocations. Range
operations still clip to the actual class capacity, including the partial SGPR
word. Ordinary/special class separation and ascending iteration remain unchanged.
Callbacks that modify later ordinary members retain forward-iteration behavior.

An isolated GCC 15 `-O3` benchmark iterates 4,096 sets 100 times with a checksum
callback. Sparse / denser / completely full cases take 361.064 / 376.090 /
349.114 ms before and 8.319 / 35.436 / 20.472 ms with the combined iterator.
Checksums match in all cases. These synthetic helper results are not projected
as workload speedups. An initial sparse-only implementation was rejected after
it made completely full sets slower; the full-word path addresses that case.

Three new regression tests compare mutations and set algebra against independent
bitsets, exercise class limits and high VGPR banks, and cover sparse/full-word
callback edits. All three pass standalone with Clang and undefined-behavior
checking. Existing special-register tests remain applicable. The initial
sparse-only implementation also passed 1,755 focused analysis/ConSan tests;
final implementation results are recorded below after the final rebuild.
