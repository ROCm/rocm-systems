# Decoder Gap Audit

This directory records the long-running ISA manual/XML/rocjitsu audit for the
`users/lua1235/decoder-gaps` branch.

## Scope

For each audited architecture, keep two reports:

- `<arch>-manual-vs-xml.md`: semantic, legality, encoding, and state details
  present in the prose manual but missing, ambiguous, or contradicted by the
  checked-in machine-readable ISA XML.
- `<arch>-rocjitsu-gaps.md`: places where rocjitsu decode, disassembly,
  autogenerated constructors, or execution semantics do not model the manual
  behavior, or depend on incomplete XML in a way that should be tested/fixed.

## Status

This is an incremental audit. A report for an architecture is not complete until
its coverage table says every manual chapter/section has been audited.

The chapter-level backlog is tracked in `audit-scope.md`. The current
FP8/BF8 conversion entries are only the first cross-architecture slice of that
backlog; they should not be read as completion of the surrounding vector, matrix,
memory, scalar, export, or microcode chapters.

## Local Tools

- `tools/manual_xml_inventory.py` compares generated markdown instruction
  headings in one manual section with checked-in XML instruction encodings.
  Example:

  ```bash
  python3 emulation/rocjitsu/audits/decoder-gaps/tools/manual_xml_inventory.py \
    rdna4 --section 16.20 \
    --encoding ENC_VFLAT --encoding ENC_VSCRATCH --encoding ENC_VGLOBAL
  ```

  The tool is an inventory harness only. XML/manual semantic gaps still need
  prose review against the markdown/PDF manuals, especially where the XML has a
  mnemonic but omits update predicates, side effects, legality rules, or flags.

- `tools/rocjitsu_llvm_decode_fuzz.py` compares generated rocjitsu raw
  encoding fixtures with LLVM's AMDGPU disassembler. It builds the helper probe
  `tools/rocjitsu_decode_probe.cpp` into `/tmp` by default and links it against
  the configured local rocjitsu build.

  ```bash
  python3 emulation/rocjitsu/audits/decoder-gaps/tools/rocjitsu_llvm_decode_fuzz.py \
    rdna4 --section 16.5 --limit 30
  ```

  The raw fixtures are useful for decoder-table and disassembly smoke fuzzing,
  but some generated default operands are not legal LLVM encodings. For example,
  RDNA4 VFLAT fixtures leave `saddr` as zero where LLVM's assembler/disassembler
  expects the encoded null value, so memory-family `llvm_invalid` results need
  follow-up with legal operand mutation before being treated as rocjitsu bugs.
