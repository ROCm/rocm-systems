# Schema 3.0.1 usage

The profiler-hub writer supports schema 3.0.0 and 3.0.1. 3.0.1 is the version
rocprofiler-systems writes. 3.0.2 and later have no writer: constructing
`writer_t` throws `std::invalid_argument`.

A full example is `usage_example/installed_usage/installed_usage.cpp`. The same
sequence is checked by `tests/unit/schema_301_usage_test.cpp`.

## Scenarios

These follow `rocpd_processor.cpp` in rocprofiler-systems.

| Scenario | Writer call | Inputs set |
|---|---|---|
| Node, process, thread | `register_node_info`, `register_process_info`, `register_thread_info` | ids, command, environment, thread name, timestamps |
| CPU, GPU, and NIC agents | `register_agent_info` | type `CPU` / `GPU` / `NIC`, name, model, vendor, product |
| PMC descriptions | `register_pmc_info` | `SQ_WAVES` on GPU (`ABS`), `NIC_BYTES` on NIC (`ACCUM`) |
| Queue, stream, code object, kernel symbol, track | `register_*` | queue 30, stream 40, `FILE` code object, `vector_add` symbol |
| `region_sample` | `insert_region_data` | `hipLaunchKernel`, one argument, call stack |
| `kernel_dispatch_sample` | `insert_kernel_dispatch_data` | grid 256x1x1, workgroup 64x1x1, scratch sizes |
| `memory_copy_sample` | `insert_memory_copy_data` | `HOST_TO_DEVICE`, 4096 bytes, CPU source, GPU destination |
| `memory_allocate_sample` | `insert_memory_alloc_data` | `ALLOC`/`REAL`, `FREE`/`VIRTUAL`, `REALLOC`/`SCRATCH` |
| `pmc_event_with_sample` | `insert_pmc_event_data` | `SQ_WAVES` = 12.5 on the `main` track |

`NIC` is a 3.0.1 agent type. Schema 3.0.0 accepts the same writer, but its
agent check is only `CPU` and `GPU`.

## Versions with no writer

| Version | What the writer does |
|---|---|
| 3.0.0, 3.0.1 | Writes the rows above |
| 3.0.2, 3.0.3, 3.0.4, 3.0.5 | Throws before `initialize_schema` |
| `version_t{}` (latest) | Throws. Latest is newer than 3.0.1 |

The error names the requested version and the two supported versions.
