# configure-policy tests

profiler-hub's `cmake/` gate makes one decision per dependency: accept what is on
`CMAKE_PREFIX_PATH`, or refuse with a message telling you what to do about it. The accept
half is exercised by every build. The refuse half is exercised by nothing — a CI job with
the dependencies installed never sees it, and a job with none of them installed fails at
the first gate and never reaches the second.

These tests drive the whole table, offline, in about five seconds.

## Running

```sh
python3 tests/configure_policy/run_configure_policy_tests.py
```

Python 3.9+ and `cmake` 3.23 or newer on `PATH`; no other dependencies, and nothing is
installed or downloaded. The cmake floor is checked rather than assumed — hermeticity rests
on `CMAKE_IGNORE_PREFIX_PATH`, which older versions treat as just another unset variable
rather than an error, so the suite would run green with the guard silently inert. Useful flags: `--only <regex>` to run a subset, `--verbose` to print each
case's output, `--work-dir <dir>` to keep the build trees, and `--source-dir <dir>` to
point at a copy of profiler-hub rather than this one.

Exit status is 0 if every case behaved as specified, 1 if any did not, 2 if the host
cannot give a trustworthy answer.

## How it works

A stand-in package is what config-mode `find_package()` actually reads, and nothing else:

- `<Package>Config.cmake` — declares the imported targets, as `INTERFACE IMPORTED`.
- `<Package>ConfigVersion.cmake` — generated by CMake's own
  `write_basic_package_version_file()`.

`make_standin.cmake` writes both. There is no library and no header behind them, so a
stand-in is valid for a *configure* and nothing more. That is the whole trick: the gate is
a configure-time decision, so a configure-time forgery is enough to drive every branch of
it, at no build cost.

The version file is generated rather than hand-written on purpose — the accept/refuse
decision is then made by the same code a real package's version file runs, not by a
re-implementation of it.

### How close a stand-in is to the real thing

Close enough to diff. Against the fmt 9.1.0 installed on this host, the generated
`fmtConfigVersion.cmake` and the shipped one differ in exactly one way: the shipped file
carries an `if("FALSE") ... return() endif()` header-only guard, which never fires. Every
line that participates in the decision is identical, because both files came out of
`write_basic_package_version_file()`.

That diff is worth running, and not only for reassurance — it is how a real defect was
found. `write_basic_package_version_file()` bakes `CMAKE_SIZEOF_VOID_P` into the version
file so a 64-bit package is refused by a 32-bit consumer. In `cmake -P` script mode that
variable is empty, and the generated file then short-circuits past its own architecture
check. The stand-ins were quietly **more permissive** than the packages they stood in for:
a case could have gone green on an accept the real world would have refused.

`make_standin.cmake` now requires `-DSIZEOF_VOID_P=`, and the runner reads the real value
out of a `LANGUAGES CXX` probe and threads it through. `fmt_wrong_architecture` stages a
correctly-versioned fmt with the wrong pointer size and requires the gate to refuse it, so
the check cannot silently lapse again.

The `Config.cmake` half is *not* faithful and is not trying to be — a real one defines
targets with include paths, a library to link, and often transitive `find_dependency()`
calls. A stand-in declares the target name and, where the gate reads them, its compile
definitions. That is the whole surface the gate touches.

### COMPATIBILITY is per-package, and it matters

`write_basic_package_version_file()` takes a `COMPATIBILITY` mode, and the five upstreams
do not agree on one:

| package         | mode               |
| --------------- | ------------------ |
| `fmt`           | `AnyNewerVersion`  |
| `spdlog`        | `SameMajorVersion` |
| `nlohmann_json` | `SameMajorVersion` |
| `GTest`         | `AnyNewerVersion`  |
| `benchmark`     | `SameMajorVersion` |

Each stand-in is generated with the mode its real upstream uses. A suite that picked one
mode for all five would be green against a world that does not exist, and would miss that
the gate treats a next-major release differently depending on which dependency it is —
see `*_next_major` in the table.

## What is staged, and what is not

`cmake/sqlite3.cmake` is not part of the gate: it clones and configures SQLite at configure
time regardless of `PROFILER_HUB_FETCH_DEPENDENCIES`. Letting it run would put a download
in front of every case. Both of its "already have it" guards test for files under
`${PROJECT_BINARY_DIR}`, so the runner writes placeholders there and the clone is skipped.
Nothing is compiled from them — the suite configures and never builds. No file under
`cmake/` is touched to achieve this.

`rocprofiler-sdk-rocpd` is not a `find_package()` dependency at all; it is a schema
directory, with a three-way gate (in-tree / refuse / clone). Its "absent" arm is reached by
pointing `ROCPD_SCHEMA_VERSION` at a version that has no directory, which needs no files
deleted.

## Hermeticity

A case is only meaningful if it sees exactly what the suite staged. Config-mode search does
*not* stop at a version-rejected candidate — it keeps looking — so a real package installed
on the host can satisfy a case meant to find nothing, or rescue a deliberately-too-old one,
and the case still reports green.

The runner therefore disables the CMake package registries, reads
`CMAKE_SYSTEM_PREFIX_PATH` back out of CMake and passes all of it to
`CMAKE_IGNORE_PREFIX_PATH`, and then re-runs the probe to confirm nothing is still visible.
If something is, it prints what and exits 2 rather than reporting results that would not
mean what they say. The ignore list is read from CMake rather than written down here, so it
holds on any platform and this directory contains no absolute paths.

`/` stays in that list. On a usrmerge host `/lib` is a symlink to `/usr/lib`, so ignoring
`/usr` alone leaves the same package reachable as `/lib/<arch>/cmake/<name>`. Ignoring a
prefix affects `find_package` only, which is why the compiler, Git and Threads are all
still found.

The re-probe catches a leak only on a host that has one of the five packages installed. On a
host that has none, it cannot tell a working ignore-list from an inert one — which is why
the cmake version is checked up front rather than left to be noticed.

This was not reasoned out in advance. It was found by breaking the gate on purpose: see
below.

## Offline

Every case runs with all proxy variables pointed at a port nothing listens on, so any
outbound connection fails in milliseconds. Kernel isolation (`unshare -rn`, `sudo unshare
--net`) would be stronger, but needs a user namespace or root and is unavailable in some of
the containers this has to run in, so it cannot be the mechanism.

Three things make the offline claim a demonstration rather than an assertion:

1. Before running anything, the suite uses the network through the block — a `git
   ls-remote` — and requires it to fail. If it succeeds, the suite says so rather than
   claiming an offline run it did not have.
2. `control_fetch_path_is_blocked` configures with `PROFILER_HUB_FETCH_DEPENDENCIES=ON` and
   nothing staged, which *must* download. It is expected to fail, and to fail inside
   FetchContent's clone step specifically — so the control cannot quietly stop
   demonstrating anything by starting to fail somewhere else.
3. Every other case asserts that neither `_deps/` nor `external/rocprofiler-sdk-rocpd/`
   was created.

## Checking that the tests can fail

Green tests prove nothing until you have watched them go red. Each of these was applied to
a throwaway copy of the source tree (`--source-dir`), never to the checkout:

| break applied to the gate                                    | cases that caught it                                        |
| ------------------------------------------------------------ | ----------------------------------------------------------- |
| `spdlog`'s `SPDLOG_FMT_EXTERNAL` check disabled               | `spdlog_without_fmt_external`                               |
| version floor dropped from `find_package(fmt ...)`            | `fmt_below_floor`                                           |
| `-DPROFILER_HUB_BUILD_TESTS=OFF` hint removed from `gtest`'s refusal | `GTest_below_floor`, `GTest_absent`                  |
| rocpd's absent-schema `FATAL_ERROR` downgraded to `WARNING`   | `rocpd_absent`                                              |
| `nlohmann_json`'s `NOT ..._FOUND` branch made unreachable     | `nlohmann_json_below_floor`, `_absent`, `_next_major`       |

The third row is the reason the refusals are matched on content and not merely on exit
status: a gate that refuses without saying what to do about it is still broken.

One case guards the fixtures rather than the gate: `fmt_wrong_architecture` goes red if
`make_standin.cmake` ever stops baking a pointer size into its version files, which is a
way the stand-ins could drift into being more permissive than real packages without any
case failing.

## Known limits

- **Configure only.** A stand-in has no code behind it, so nothing here says the project
  *builds* against a given dependency version. This tests the policy, not the ABI.
- **The floors are read, not asserted.** The runner parses each floor out of its
  `cmake/*.cmake` file, so a deliberate floor bump does not turn the suite red. Nothing here
  will tell you a floor changed — that is the gate-shape lint's job, not this suite's.
- **The fetch arm is one case deep.** `PROFILER_HUB_FETCH_DEPENDENCIES=ON` is only
  exercised far enough to show it tries to download. What it does once it succeeds needs
  the network and is out of scope.
- **rocpd's clone arm is untested.** Its refusal message naming the schema version and the
  branch lives on that arm, so no offline case reaches it.

## Why this is not a ctest test

It is deliberately not registered with `add_test()`, for the same reason
`tests/find_package/` is not: reaching ctest means the project already configured, which
means the accept path already passed. Every refuse case would be unreachable from inside
the build it is testing.

It also needs to run where profiler-hub *cannot* be configured — that is the interesting
case — and it needs to run without the dependencies installed, which is exactly the state a
ctest run cannot be in. A standalone script needs nothing but `cmake` and Python, so it can
run on a bare container, in a pre-commit hook, or as its own CI job.
