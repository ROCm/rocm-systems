# Focused CDNA5 WMMA v4 provider

The experiment uses the five existing CDNA5 `16x16x32` FP16/BF16 WMMA forms: F32/F16, F16/F16, F32/BF16, BF16/BF16, and BF16F32/BF16. Their v3 handlers and generated callback table remain the fallback. EXP/LOG code already present in this worktree is held constant in every comparison.

## Callback and build layout

The AMD ISA generator emits one focused v4 translation unit containing distinct, non-member execute callbacks for those five forms. Each callback performs the same operand resolution and invokes the existing `mma_exec.h` specialization; it does not define a second copy of any generated `execute_impl` symbol. The callback, its header-defined WMMA helpers, and their SIMD loops compile with `-O3 -march=x86-64-v4`. Other CDNA5 execution code retains the x86-64-v3 baseline.

One CMake option selects `off`, `combined`, or `dso`, defaulting to `off`. `combined` links the focused v4 object into `librocjitsu.so`; `dso` links the same object target into a sibling `librocjitsu_cdna5_wmma_v4.so`. The provider must not link another copy of ISA, VM, or execution-backend objects. Both measured layouts use the same source, compiler, optimization and LTO settings. The experimental overlay applies to the shared-library simulator; independently object-composed CLI and test images retain their baseline CDNA5 callbacks. The model-only gfx1250 translator stays execution-free.

## Provider boundary and selection

The DSO exports one versioned C getter returning a private descriptor with an ABI revision, build-compatibility digest and five typed `Instruction::ExecuteFn` pointers. All other provider symbols are hidden. The digest is generated at configure time from the provider ABI header, relevant generated CDNA5 execution sources and WMMA helper header, compiler identity and effective compile options; CMake tracks those inputs for reconfiguration. It is a pairing guard for this experiment, not a stable external ABI. A small, audited set of core operations used by the callbacks is explicitly exported from `librocjitsu.so`; a final provider link with `-z defs` and a dynamic-symbol audit must establish that no other private core dependency escaped. The provider is linked against `librocjitsu.so`, not against duplicate core objects.

Before the first shared-library CDNA5 decode, the baseline code checks CPU features and OS-enabled AVX-512 state. In `dso` mode it resolves the provider by an absolute sibling path derived from the loaded `librocjitsu.so`, then opens it with `RTLD_NOW | RTLD_LOCAL`, validates the descriptor and keeps it loaded for the process lifetime. In `combined` mode it reads the same descriptor from the linked v4 object. The baseline copies the immutable generated callback table, replaces only the five named entries, and keeps the original operand backend; generated constructors then cache the selected direct callback at decode. No ISA branch or `dlsym` occurs during instruction execution.

`RJ_CDNA5_WMMA_BACKEND=auto|v3|v4` permits qualification. `auto` falls back to v3 if the CPU/OS is unsuitable or the DSO is missing or incompatible. `v3` forces the baseline table. `v4` reports an error rather than executing unsupported instructions or silently falling back. `RJ_FORCE_SCALAR=1` bypasses v4 selection so the existing scalar oracle remains authoritative. No provider initializer or v4 function may execute before the capability check.

## Qualification and comparison

Tests must verify all five decoded forms against the scalar oracle, including aliasing, modifiers, non-finite values and the existing exact-test cases; verify `auto` and forced-v3 fallback; reject missing or mismatched providers; and assert the selected callback's module. A benchmark that calls `mma_exec.h` directly is not evidence of provider speed. The primary A/B times warmed, predecoded CDNA5 instructions through `librocjitsu.so` for all five forms. Run one gfx1250 FP16 and one BF16 GEMM workload at `--cpu-thread-budget=1` if the local harness supports them; otherwise report that limitation and do not extrapolate microbenchmark timing to workload speed. Fresh processes set `RJ_FORCE_SCALAR` before launch because its test override is module-local.

Report at least seven interleaved combined-versus-DSO runs on the same host and compiler, with median and range for each decoded form and cold provider-load time separately. These are host-simulator timings, not GPU hardware timings. Measure stripped `librocjitsu.so`, stripped provider, their combined installed bytes, `.text` and `.rodata`; report the incremental WMMA delta because this worktree already embeds EXP/LOG v4 code. Inspect compile commands, symbols and disassembly to confirm that only the focused object uses v4 instructions, the selected callback reaches its v4 specialization, and any difference in inlining or call edges. A native whole-library v4 build may be shown only as a reference, not as the packaging A/B. Final shared-library linking and execution tests are required; object inspection alone is insufficient.
